# Feature: นำเข้าข้อมูลเดิม (Import Legacy Data)
Spec ID: SPEC-IMP-008 | Source: UC-08 (Use Case Table) | Use case: UC-08
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
เจ้าหน้าที่กองกิจการนักศึกษา (หรือผู้ดูแลระบบตอนติดตั้งครั้งแรก) นำเข้าข้อมูลกิจกรรมและรายชื่อ
ผู้สมัครเดิมจากไฟล์ Google Forms/Microsoft Excel เข้าสู่ระบบใหม่ เพื่อให้สโมสรรุ่นก่อนสืบค้น
ประวัติกิจกรรมเก่าได้ และกองกิจไม่ต้องเสียข้อมูลชั่วโมงย้อนหลัง

## Scope
### In scope
- เลือกฟังก์ชัน "นำเข้าข้อมูลเดิม" และอัปโหลดไฟล์ Excel/CSV ที่ export จาก Google Forms
- ตรวจสอบโครงสร้างไฟล์ที่อัปโหลด และแสดงตัวอย่างข้อมูลก่อน import
- ยืนยันนำเข้า และบันทึกข้อมูลเข้าฐานข้อมูล
- ให้ข้อมูลกิจกรรมที่นำเข้าสำเร็จ ปรากฏและสืบค้นได้ในระบบใหม่
- ตรวจจับไฟล์ที่รูปแบบไม่ตรงตามที่รองรับ แจ้ง error พร้อมระบุแถวที่ผิดพลาด และไม่ import
  ข้อมูลทิ้งไว้แบบครึ่ง ๆ กลาง ๆ
### Out of scope
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- การสร้างไฟล์ export จาก Google Forms/Excel เอง (อยู่นอกระบบ)
- การแก้ไขข้อมูลที่นำเข้าไปแล้วภายหลัง (ไม่ได้ระบุใน use case นี้)
- การนำเข้าข้อมูลประเภทอื่นนอกจากกิจกรรม/รายชื่อผู้สมัครเดิม (เช่น ชั่วโมงที่บันทึกใน REG แล้ว)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-FMT-01 ระบบต้องรองรับไฟล์ Excel/CSV ที่ export จาก Google Forms ตามโครงสร้างที่กำหนด
  (รายละเอียดคอลัมน์/ประเภทข้อมูลที่รองรับยังไม่ระบุในตาราง - ดู Q-02)
- DOM-ATOMIC-01 ระบบต้องไม่ import ข้อมูลที่พบปัญหาทิ้งไว้แบบครึ่ง ๆ กลาง ๆ
  (พฤติกรรมที่แน่นอนยังไม่ยืนยัน - ดู Q-01)

## Requirements
- FR-IMP-01 ระบบต้องให้ผู้ใช้เลือกฟังก์ชัน "นำเข้าข้อมูลเดิม" และอัปโหลดไฟล์ Excel/CSV
  ที่ export จาก Google Forms                                            <- UC-08 Main Flow ขั้น 1-2
- FR-IMP-02 ระบบต้องตรวจสอบโครงสร้างไฟล์ที่อัปโหลด และแสดงตัวอย่างข้อมูลให้ผู้ใช้ตรวจสอบก่อน import
                                                                        <- UC-08 Main Flow ขั้น 3
- FR-IMP-03 เมื่อผู้ใช้ยืนยันนำเข้า ระบบต้องบันทึกข้อมูลเข้าฐานข้อมูล
                                                                        <- UC-08 Main Flow ขั้น 4-5
- FR-IMP-04 ข้อมูลกิจกรรมที่นำเข้าสำเร็จ ต้องปรากฏในระบบใหม่และสามารถสืบค้นได้
                                                                        <- UC-08 Postcondition
- FR-IMP-05 หากไฟล์มีรูปแบบไม่ตรงตามที่ระบบรองรับ ระบบต้องแจ้ง error พร้อมระบุแถวที่ผิดพลาด
  และต้องไม่ import ข้อมูลบางส่วนทิ้งไว้แบบครึ่ง ๆ กลาง ๆ                      <- UC-08 Exception Flow 3a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์นำเข้าข้อมูลเดิม ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-IMP-01 (FR-IMP-03, FR-IMP-04)
      Given ไฟล์มีโครงสร้างถูกต้องตามที่ระบบรองรับ
      When  ผู้ใช้ยืนยันนำเข้า
      Then  ข้อมูลทั้งหมดถูกบันทึกและค้นหาได้
- [ ] AC-IMP-02 (FR-IMP-05)
      Given ไฟล์มีบางแถวรูปแบบผิด
      When  ระบบตรวจพบ
      Then  ระบบแจ้ง error พร้อมเลขแถวที่ผิด และไม่ import ข้อมูลบางส่วนทิ้งไว้
- [ ] AC-IMP-03 (FR-IMP-01)
      Given ผู้ใช้เลือก "นำเข้าข้อมูลเดิม"
      When  ผู้ใช้อัปโหลดไฟล์ Excel/CSV
      Then  ระบบรับไฟล์และเตรียมตรวจสอบโครงสร้าง
- [ ] AC-IMP-04 (FR-IMP-02)
      Given ผู้ใช้อัปโหลดไฟล์แล้ว
      When  ระบบตรวจสอบโครงสร้างไฟล์เสร็จ
      Then  ระบบแสดงตัวอย่างข้อมูลให้ผู้ใช้ตรวจสอบก่อนกดยืนยันนำเข้า
- [ ] AC-IMP-05 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์นำเข้าข้อมูลเดิม
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 "ไม่ import ข้อมูลบางส่วนทิ้งไว้ครึ่ง ๆ กลาง ๆ" ตีความเบื้องต้นว่าเป็นพฤติกรรม all-or-nothing
  ต่อการ import ครั้งนั้น (ถ้ามีแถวผิดพลาด ระบบไม่บันทึกแถวใดเลยจากไฟล์นั้นจนกว่าจะแก้ไข) - ยังไม่ยืนยัน (ดู Q-01)
- Q-01 พฤติกรรมที่แน่นอนของ "ไม่ import บางส่วนทิ้งไว้ครึ่ง ๆ กลาง ๆ": ปฏิเสธทั้งไฟล์ (all-or-nothing)
  หรือ import เฉพาะแถวที่ถูกต้องแล้วข้ามแถวที่ผิดพร้อมรายงานแยก (partial import + report)?
- Q-02 โครงสร้างไฟล์ที่ระบบรองรับ (คอลัมน์ที่จำเป็น, ประเภทข้อมูลแต่ละคอลัมน์) มีรายละเอียดอย่างไร
  ไม่ได้ระบุในตาราง
- Q-03 หากนำเข้าข้อมูลกิจกรรมเดิมที่มี "ชื่อโครงการ" ซ้ำกับที่มีอยู่แล้วในระบบ ระบบจัดการอย่างไร
  (สร้างรายการซ้ำ / merge / แจ้งเตือนให้ผู้ใช้ตัดสินใจ) - ไม่มี exception ระบุกรณีนี้ในตาราง
- Q-04 ขนาดไฟล์สูงสุดและจำนวนแถวสูงสุดที่รองรับต่อการนำเข้าหนึ่งครั้ง ไม่ได้ระบุในตาราง
- Q-05 ฟีเจอร์นี้จำกัดสิทธิ์เฉพาะเจ้าหน้าที่กองกิจ/ผู้ดูแลระบบเท่านั้น หรือผู้ใช้ที่ login แล้วทุกคน
  เข้าถึงได้ (Primary Actor ระบุ "เจ้าหน้าที่กองกิจ...หรือผู้ดูแลระบบ" แต่ไม่มี constraint สิทธิ์
  เฉพาะนอกจาก Login ทั่วไป)
