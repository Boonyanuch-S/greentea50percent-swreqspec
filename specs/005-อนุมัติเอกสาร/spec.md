## Goal
อาจารย์ที่ปรึกษาสโมสรตรวจสอบรายการเอกสารโครงการทั้งชุดและเลือกเปิดดูเอกสารแต่ละรายการในหน้าอนุมัติ อนุมัติเนื้อหาออนไลน์
แล้วเซ็นและอัปโหลดใบปะหน้าเฉพาะส่วนที่เกี่ยวกับงบประมาณ เพื่อให้กรรมการสโมสรทราบผล
การอนุมัติได้เร็ว โดยไม่ต้องรอเซ็นเอกสารกระดาษทั้งชุด

## Scope
### In scope
- แสดงรายการเอกสารโครงการทั้งชุดในหน้าอนุมัติ และให้อาจารย์เลือกเปิดดูเอกสารแต่ละรายการ (เล่มโครงการ, กส 002, ใบแนบกิจกรรม)
- ให้อาจารย์ตรวจวัตถุประสงค์ ตัวชี้วัด และรูปแบบของเอกสาร
- อนุมัติเนื้อหาออนไลน์ และบันทึกวันเวลาที่อนุมัติ
- แจ้งให้พิมพ์เฉพาะใบปะหน้าเพื่อขอลายเซ็นจริง
- รับไฟล์ใบปะหน้าที่เซ็นแล้ว (อัปโหลด) และเปลี่ยนสถานะเอกสารเป็น "รออนุมัติ"
- รองรับการตรวจสอบโดยกองกิจ การตีกลับพร้อมคอมเมนต์ และเปลี่ยนสถานะเป็น "อนุมัติสมบูรณ์" เมื่อกองกิจตรวจสอบผ่าน
- แจ้งกรรมการสโมสรผ่าน UC-10 เมื่ออนุมัติสมบูรณ์
- ส่งเอกสารกลับพร้อมความเห็น เมื่ออาจารย์ไม่เห็นด้วยกับเอกสารบางส่วน (ย้อนกลับ UC-01)
- แสดงคำเตือนเมื่อเนื้อหาต้องสงสัยว่าอาจมาจาก AI โดยไม่บล็อกการอนุมัติอัตโนมัติ
### Out of scope
- การส่งต่อเอกสารจากเจ้าหน้าที่คณะ (UC-03) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition/trigger)
- เนื้อหา/ช่องทางการแจ้งอีเมลกลับกรรมการสโมสร (UC-10)
- การแก้ไขเอกสารโครงการโดยกรรมการสโมสรหลังถูกส่งกลับ (UC-01)
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- กลไกตรวจจับเนื้อหา AI-generated ที่แม่นยำ/อัตโนมัติ (ระบบเพียงแสดงคำเตือนเท่านั้น - ดู Q-02)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-UC10-01 เมื่อสถานะเปลี่ยนเป็น "อนุมัติสมบูรณ์" ระบบต้องเรียก UC-10 เพื่อแจ้งกรรมการสโมสร
- IF-UC01-02 เมื่ออาจารย์ส่งกลับพร้อมความเห็น ระบบต้องส่งเอกสารกลับไปที่ UC-01
- IF-UPLOAD-01 ระบบต้องรองรับการอัปโหลดไฟล์ใบปะหน้าที่เซ็นแล้ว (สแกน/รูปถ่าย) กลับเข้าสู่ระบบ

## Requirements
- FR-APR-01 ระบบต้องแสดงรายการเอกสารโครงการทั้งชุดในหน้าอนุมัติ และให้อาจารย์เลือกเปิดดูเอกสารแต่ละรายการ
  (เล่มโครงการ, กส 002, ใบแนบกิจกรรม) เมื่อเปิดเอกสารที่รออนุมัติ  <- UC-05 Main Flow ขั้น 1-2
- FR-APR-02 ระบบต้องให้อาจารย์ตรวจสอบวัตถุประสงค์ ตัวชี้วัด และรูปแบบของเอกสาร ก่อนตัดสินใจ
                                                                        <- UC-05 Main Flow ขั้น 3
- FR-APR-03 เมื่ออาจารย์กดอนุมัติเนื้อหาออนไลน์ ระบบต้องบันทึกวันเวลาที่อนุมัติ และแจ้งให้อาจารย์
  พิมพ์เฉพาะใบปะหน้าเพื่อขอลายเซ็นจริง                                     <- UC-05 Main Flow ขั้น 4-5
- FR-APR-04 ระบบต้องให้อาจารย์อัปโหลดไฟล์ใบปะหน้าที่เซ็นแล้วกลับเข้าสู่ระบบ และเปลี่ยนสถานะเอกสารเป็น "รออนุมัติ"
                                                                        <- UC-05 Main Flow ขั้น 6
- FR-APR-05 เมื่อกองกิจตรวจสอบเอกสารที่มีสถานะ "รออนุมัติ" ผ่านแล้ว ระบบต้องเปลี่ยนสถานะเอกสารเป็น
  "อนุมัติสมบูรณ์" และเรียก UC-10 เพื่อแจ้งกรรมการสโมสร                         <- UC-05 Main Flow ขั้น 7 / Postcondition
- FR-APR-06 เมื่อกองกิจไม่เห็นด้วยกับเอกสาร ระบบต้องส่งเอกสารทั้งชุดกลับพร้อมคอมเมนต์รายละเอียดที่ต้องแก้ไข
  และเมื่อกองกิจตรวจสอบผ่าน ระบบต้องเปลี่ยนสถานะเป็น "อนุมัติสมบูรณ์"       <- UC-05 Alternative Flow 3a
- FR-APR-07 หากเนื้อหาเอกสารมีลักษณะคล้ายถูกสร้างจาก AI โดยไม่ผ่านการตรวจสอบ ระบบควรแสดงคำเตือน
  ให้อาจารย์ตรวจสอบละเอียดขึ้น แต่ต้องไม่ปฏิเสธหรือบล็อกการอนุมัติโดยอัตโนมัติ    <- UC-05 Exception Flow 3b

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์อนุมัติเอกสาร ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-APR-01 (FR-APR-03)
      Given เอกสารครบทั้งชุดแล้ว
      When  อาจารย์กดอนุมัติเนื้อหาออนไลน์
      Then  ระบบบันทึกวันเวลาอนุมัติ และแจ้งให้พิมพ์ใบปะหน้า
- [ ] AC-APR-02 (FR-APR-04, FR-APR-05)
  Given อาจารย์อัปโหลดใบปะหน้าที่เซ็นแล้ว และระบบรับไฟล์
  When  กองกิจตรวจสอบเอกสารและให้ผ่าน
  Then  สถานะเปลี่ยนจาก "รออนุมัติ" เป็น "อนุมัติสมบูรณ์" และระบบเรียก UC-10 เพื่อแจ้งกรรมการสโมสร
- [ ] AC-APR-03 (FR-APR-01)
      Given มีเอกสารโครงการที่รออนุมัติ
      When  อาจารย์เปิดหน้าอนุมัติและเลือกเอกสารรายการหนึ่ง
      Then  ระบบเปิดแสดงเอกสารรายการที่เลือก โดยมีรายการเอกสารทั้งชุดให้เลือกดู
- [ ] AC-APR-04 (FR-APR-06)
  Given กองกิจตรวจสอบเอกสารแล้วไม่เห็นด้วย
  When  กองกิจกดตีกลับและกรอกคอมเมนต์รายละเอียดที่ต้องแก้ไข
  Then  ระบบส่งเอกสารทั้งชุดกลับไปยัง UC-01 พร้อมคอมเมนต์ครบถ้วน
- [ ] AC-APR-05 (FR-APR-07)
      Given เนื้อหาเอกสารมีลักษณะคล้ายถูกสร้างจาก AI โดยไม่ผ่านการตรวจสอบ
      When  อาจารย์เปิดตรวจเอกสาร
      Then  ระบบแสดงคำเตือนให้ตรวจสอบละเอียดขึ้น โดยไม่ปฏิเสธหรือบล็อกการอนุมัติอัตโนมัติ
- [ ] AC-APR-06 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์อนุมัติเอกสาร
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 "เนื้อหา" กับ "ใบปะหน้า (งบประมาณ)" เป็นสองขั้นตอนแยกกัน: อนุมัติเนื้อหาออนไลน์ก่อน (ขั้น 4)
  แล้วจึงต้องมีลายเซ็นจริงของใบปะหน้าตามมา (ขั้น 6) ก่อนเอกสารจะเปลี่ยนเป็น "อนุมัติสมบูรณ์"
- Q-01 หากอาจารย์กดอนุมัติเนื้อหาแล้ว (ขั้น 4) แต่ไม่อัปโหลดใบปะหน้าที่เซ็นแล้วภายในเวลาที่กำหนด
  ระบบมีการติดตาม/แจ้งเตือนอย่างไร (ไม่มี exception ระบุไว้ในตารางสำหรับกรณีนี้)
- Q-02 เกณฑ์การตรวจจับเนื้อหา "คล้ายถูกลอกจาก AI" (Exception 3b) เป็นการตรวจจับอัตโนมัติของระบบ
  หรือเป็นดุลพินิจของอาจารย์เอง ต้นฉบับเขียนเพียงว่า "ระบบอาจแสดงคำเตือน" -> ต้องยืนยันว่าระบบมีกลไก
  ตรวจจับจริงหรือไม่ หรือเป็นเพียงข้อความเตือนทั่วไปที่แสดงทุกครั้ง
- Q-03 รูปแบบไฟล์ใบปะหน้าที่อัปโหลดได้ (PDF/รูปภาพ) และขนาดไฟล์สูงสุด ไม่ได้ระบุในตาราง
- ASM-02 หลังอาจารย์อัปโหลดใบปะหน้าที่เซ็นแล้ว เอกสารมีสถานะ "รออนุมัติ" กองกิจเป็นผู้ตรวจสอบ
  และสามารถตีกลับพร้อมคอมเมนต์รายละเอียดที่ต้องแก้ไขได้ เมื่อกองกิจตรวจสอบผ่านจึงเปลี่ยนเป็น "อนุมัติสมบูรณ์"
