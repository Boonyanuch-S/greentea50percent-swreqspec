# Feature: จัดทำเล่มสรุปโครงการ (Prepare Project Summary Book)
Spec ID: SPEC-SUM-004 | Source: use-case-specifications.md | Use case: UC-04
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
เจ้าหน้าที่คณะวิทยาศาสตร์รวบรวมข้อมูลหลังกิจกรรมจบ (งบประมาณ ผลประเมิน ภาพกิจกรรม)
จัดทำเป็นเล่มสรุปโครงการและอัปโหลดเข้าระบบ เพื่อปลดล็อกให้กรรมการสโมสรส่งข้อมูลชั่วโมงกิจกรรมต่อได้
(UC-02) และให้เจ้าหน้าที่กองกิจใช้ประกอบการตรวจสอบชั่วโมง (UC-07)

## Scope
### In scope
- เปิดดูโครงการที่กิจกรรมจบแล้ว
- รวบรวมข้อมูลงบประมาณและผลประเมินของโครงการนั้น
- จัดทำเล่มสรุปโครงการและอัปโหลดเข้าระบบ
- แจ้งกรรมการสโมสรทันทีว่าเล่มสรุปพร้อมใช้แล้ว และปลดล็อกให้ส่งข้อมูลชั่วโมงต่อได้ (UC-02)
- แสดงสถานะ "รอสรุปงบ" ให้กรรมการสโมสรเห็นได้ ระหว่างที่รอเหรัญญิกสรุปงบล่าช้า
### Out of scope
- การสรุปงบประมาณโดยเหรัญญิก (เป็นเหตุการณ์ภายนอกที่กระตุ้น Trigger ของฟีเจอร์นี้ - ดู Q-01)
- การส่งข้อมูลชั่วโมงกิจกรรม (UC-02) - ฟีเจอร์นี้เพียงปลดล็อกให้ทำได้ ไม่ได้ทำเอง
- การตรวจสอบไฟล์ชั่วโมงโดยเจ้าหน้าที่กองกิจ (UC-07) - เล่มสรุปเป็นเพียงเอกสารประกอบการตรวจ
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-UC02-01 เล่มสรุปโครงการที่อัปโหลดสำเร็จ เป็น precondition ที่ปลดล็อกให้กรรมการสโมสร
  ส่งข้อมูลชั่วโมงได้ใน UC-02
- IF-UC07-03 เล่มสรุปโครงการต้องพร้อมให้เจ้าหน้าที่กองกิจเรียกดูประกอบการตรวจสอบใน UC-07
  (อ้างอิง Alternative Flow 3a ของ UC-07)

## Requirements
- FR-SUM-01 ระบบต้องให้เจ้าหน้าที่คณะเปิดดูโครงการที่กิจกรรมจบแล้วได้
                                                                        <- UC-04 Main Flow ขั้น 1
- FR-SUM-02 ระบบต้องให้เจ้าหน้าที่รวบรวมข้อมูลงบประมาณและผลประเมินของโครงการนั้น
                                                                        <- UC-04 Main Flow ขั้น 2
- FR-SUM-03 ระบบต้องให้เจ้าหน้าที่จัดทำเล่มสรุปโครงการและอัปโหลดเข้าระบบ
                                                                        <- UC-04 Main Flow ขั้น 3
- FR-SUM-04 เมื่ออัปโหลดเล่มสรุปสำเร็จ ระบบต้องแจ้งกรรมการสโมสรทันทีว่าเล่มสรุปพร้อมใช้แล้ว
  และปลดล็อกให้ส่งข้อมูลชั่วโมงต่อได้ (UC-02)                               <- UC-04 Main Flow ขั้น 4 / Postcondition
- FR-SUM-05 หากเหรัญญิกยังสรุปงบไม่เสร็จ ระบบต้องแสดงสถานะ "รอสรุปงบ" ให้กรรมการสโมสรเห็นได้
  ไม่ต้องปล่อยให้รอเงียบ ๆ                                                 <- UC-04 Exception Flow 2a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์จัดทำเล่มสรุปโครงการ ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-SUM-01 (FR-SUM-04)
      Given งบประมาณสรุปเสร็จแล้ว
      When  เจ้าหน้าที่อัปโหลดเล่มสรุป
      Then  ระบบแจ้งกรรมการสโมสรทันทีว่าเล่มสรุปพร้อมใช้
- [ ] AC-SUM-02 (FR-SUM-05)
      Given เหรัญญิกยังสรุปงบไม่เสร็จ
      When  กรรมการสโมสรเปิดดูสถานะโครงการ
      Then  ระบบแสดงสถานะ "รอสรุปงบ" ให้เห็น
- [ ] AC-SUM-03 (FR-SUM-01)
      Given มีโครงการที่กิจกรรมจบแล้วหลายรายการ
      When  เจ้าหน้าที่คณะเปิดดูโครงการ
      Then  ระบบอนุญาตให้เปิดเฉพาะโครงการที่กิจกรรมจบแล้วได้
- [ ] AC-SUM-04 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์จัดทำเล่มสรุปโครงการ
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 "งบประมาณสรุปเสร็จแล้ว" หมายถึงเหรัญญิกกดยืนยันสรุปงบในฟีเจอร์อื่น (ไม่ได้ระบุ use case
  ที่ชัดเจนในเอกสารต้นฉบับ 11 UC) แล้วสถานะนั้นถูกอ่านมาแสดงที่ฟีเจอร์นี้
- Q-01 การ "สรุปงบ" โดยเหรัญญิก ทำผ่าน use case ใด (ไม่มี use case แยกที่ระบุไว้ใน 11 UC ของเอกสารต้นฉบับ)
  -> ต้องยืนยันว่าอยู่นอกระบบทั้งหมด (เช่น ทำในระบบบัญชีแยกต่างหาก) หรือมี use case ที่ยังไม่ได้เขียนสเปก
- Q-02 รูปแบบ/เทมเพลตของ "เล่มสรุปโครงการ" (ประเภทไฟล์, โครงสร้างเนื้อหาที่ต้องมี) ไม่ได้ระบุรายละเอียด
  ในตารางต้นฉบับ
- Q-03 หากเจ้าหน้าที่คณะอัปโหลดเล่มสรุปผิดไฟล์หรือไม่ครบ มีช่องทางแก้ไข/อัปโหลดใหม่ทับได้หรือไม่
  (ไม่มี exception ระบุกรณีนี้ในตาราง)
