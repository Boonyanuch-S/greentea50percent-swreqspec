# แผนการพัฒนา: จัดทำเล่มสรุปโครงการ

## 1. สรุปแนวทาง
- ฟีเจอร์นี้ให้เจ้าหน้าที่คณะเปิดดูโครงการที่กิจกรรมจบแล้วตาม FR-SUM-01
- เจ้าหน้าที่รวบรวมข้อมูลงบประมาณและผลประเมินตาม FR-SUM-02
- เจ้าหน้าที่จัดทำและอัปโหลดเล่มสรุปโครงการตาม FR-SUM-03
- หลังอัปโหลดสำเร็จ ระบบแจ้งกรรมการสโมสรและปลดล็อก UC-02 ตาม FR-SUM-04 และ IF-UC02-01
- เอกสารที่อัปโหลดต้องพร้อมให้ UC-07 เรียกดู และต้องแสดงสถานะรอสรุปงบตาม FR-SUM-05 และ IF-UC07-03

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สร้างหน้ารายการโครงการ หน้าจัดทำเล่ม และหน้าสถานะตาม FR-SUM-01, FR-SUM-03, FR-SUM-05 |
| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้ให้บริการข้อมูลโครงการ การอัปโหลด และสถานะตาม FR-SUM-01 ถึง FR-SUM-05 |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บข้อมูลโครงการ สถานะงบ และข้อมูลเอกสารตาม FR-SUM-01, FR-SUM-02, FR-SUM-05; รายละเอียดแหล่งข้อมูลสถานะงบยังรอ Q-01 |
| พื้นที่จัดเก็บไฟล์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บเล่มสรุปที่อัปโหลดตาม FR-SUM-03 และ IF-UC07-03; ประเภทไฟล์และโครงสร้างยังรอ Q-02 |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Project | `project_id`, `name`, `activity_end_status`, `faculty_id` | ใช้กรองโครงการที่กิจกรรมจบแล้วตาม FR-SUM-01 |
| ProjectFinancialSummary | `project_id`, `budget_status`, `confirmed_at` | ใช้แสดงว่ารอสรุปงบหรือพร้อมจัดทำตาม FR-SUM-02, FR-SUM-05 และ ASM-01; แหล่งข้อมูลจริงยังรอ Q-01 |
| ProjectEvaluation | `evaluation_id`, `project_id`, `evaluation_data` | ใช้รวบรวมผลประเมินตาม FR-SUM-02 |
| ProjectSummaryBook | `summary_id`, `project_id`, `file_reference`, `uploaded_at`, `availability_status` | ใช้เก็บเล่มสรุปและทำให้พร้อมเรียกดูใน UC-07 ตาม FR-SUM-03 และ IF-UC07-03; รูปแบบไฟล์ยังรอ Q-02 และการอัปโหลดทับยังรอ Q-03 |
| ClubNotification | `notification_id`, `project_id`, `recipient`, `message`, `sent_at` | ใช้แจ้งกรรมการสโมสรหลังอัปโหลดตาม FR-SUM-04; ความหมายของ “ทันที” ยังไม่มีค่าระยะเวลาใน spec |
| AccessContext | `user_id`, `authenticated`, `role`, `faculty_id` | ใช้ตรวจการยืนยันตัวตนก่อนเข้าฟีเจอร์ตาม NFR-SEC-01 และจำกัดบริบทเจ้าหน้าที่ตาม FR-SUM-01 |

## 4. API / หน้าจอ

- `GET /projects/completed` รับบริบทผู้ใช้และคืนรายการโครงการที่กิจกรรมจบแล้ว รองรับ FR-SUM-01 และ NFR-SEC-01
- `GET /projects/{project_id}/summary-inputs` คืนข้อมูลงบประมาณและผลประเมินของโครงการ รองรับ FR-SUM-02 และ NFR-SEC-01
- `GET /projects/{project_id}/budget-status` คืนสถานะงบประมาณเพื่อแสดง “รอสรุปงบ” รองรับ FR-SUM-05; แหล่งสถานะยังรอ Q-01
- `POST /projects/{project_id}/summary-book` รับไฟล์เล่มสรุปและคืนสถานะการอัปโหลด รองรับ FR-SUM-03, NFR-SEC-01 และ Q-02
- `POST /projects/{project_id}/summary-book/complete` ทำให้เอกสารพร้อมใช้ แจ้งกรรมการสโมสร และปลดล็อก UC-02 รองรับ FR-SUM-04 และ IF-UC02-01; การทำงานเมื่อเชื่อมต่อไม่สำเร็จยังไม่ได้กำหนดใน spec
- `GET /projects/{project_id}/summary-book` คืนไฟล์หรือข้อมูลอ้างอิงเล่มสรุปให้ UC-07 เรียกดู รองรับ IF-UC07-03
- หน้ารายการโครงการกิจกรรมจบแล้ว แสดงเฉพาะโครงการที่เข้าเงื่อนไข รองรับ FR-SUM-01 และ AC-SUM-03
- หน้ารวบรวมข้อมูล แสดงงบประมาณและผลประเมิน รองรับ FR-SUM-02
- หน้าอัปโหลดเล่มสรุป รับไฟล์และแสดงผลสำเร็จหรือผิดพลาด รองรับ FR-SUM-03 และ Q-02; การอัปโหลดทับยังรอ Q-03
- หน้าสถานะโครงการของกรรมการสโมสร แสดง “รอสรุปงบ” หรือสถานะเล่มสรุปพร้อมใช้ รองรับ FR-SUM-04, FR-SUM-05 และ AC-SUM-01, AC-SUM-02
- ทุกหน้าตรวจสถานะการยืนยันตัวตนก่อนเข้าถึง รองรับ NFR-SEC-01 และ AC-SUM-04

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-NFR-21 | ใช้ผ่าน `AccessContext`, middleware ตรวจสิทธิ์ และทุก API/หน้าจอที่ระบุ NFR-SEC-01 | ใช้แล้ว |
| IF-UC02-01 | ใช้ในขั้นตอน `POST /projects/{project_id}/summary-book/complete` เพื่อปลดล็อกการส่งข้อมูลชั่วโมงใน UC-02 | ใช้แล้ว |
| IF-UC07-03 | ใช้ใน `GET /projects/{project_id}/summary-book` และสถานะ `availability_status` เพื่อให้ UC-07 เรียกดูเอกสาร | ใช้แล้ว |

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-SUM-01 | `test_AC_SUM_01_upload_notifies_ready` | เตรียมโครงการที่งบประมาณสรุปเสร็จแล้ว อัปโหลดเล่มสรุป แล้วตรวจว่าระบบบันทึกเอกสารพร้อมใช้และสร้างการแจ้งกรรมการสโมสรตาม FR-SUM-04 |
| AC-SUM-02 | `test_AC_SUM_02_pending_budget_status` | เตรียมโครงการที่เหรัญญิกยังสรุปงบไม่เสร็จ เปิดดูในบริบทกรรมการสโมสร แล้วตรวจข้อความ “รอสรุปงบ” ตาม FR-SUM-05 |
| AC-SUM-03 | `test_AC_SUM_03_completed_projects_only` | เตรียมโครงการทั้งที่กิจกรรมจบแล้วและยังไม่จบ เปิดหน้ารายการด้วยสิทธิ์เจ้าหน้าที่คณะ แล้วตรวจว่าแสดงเฉพาะโครงการที่กิจกรรมจบแล้วตาม FR-SUM-01 |
| AC-SUM-04 | `test_AC_SUM_04_requires_login` | เรียก API และเปิดหน้าฟีเจอร์โดยไม่มีการยืนยันตัวตน แล้วตรวจว่าระบบปฏิเสธการเข้าถึงตาม NFR-SEC-01 |

## 7. ลำดับงาน

1. กำหนดโมเดลโครงการ สถานะงบ และเอกสารตาม FR-SUM-01, FR-SUM-02, FR-SUM-03 และ Q-01 ถึง Q-03 โดยยังไม่ล็อกส่วนที่เป็น Open Questions
2. ทำ middleware ตรวจการยืนยันตัวตนตาม NFR-SEC-01 และ AC-SUM-04
3. ทำ API และหน้ารายการโครงการที่กิจกรรมจบแล้วตาม FR-SUM-01 และ AC-SUM-03
4. ทำ API และหน้ารวบรวมงบประมาณกับผลประเมินตาม FR-SUM-02
5. ทำ API และหน้าจัดทำหรืออัปโหลดเล่มสรุปตาม FR-SUM-03 และ Q-02
6. ทำการเผยแพร่เอกสารให้พร้อมใช้ การแจ้งกรรมการ และการปลดล็อก UC-02 ตาม FR-SUM-04 และ IF-UC02-01
7. ทำการแสดงสถานะ “รอสรุปงบ” ตาม FR-SUM-05 และ AC-SUM-02
8. ทำช่องทางให้ UC-07 เรียกดูเล่มสรุปตาม IF-UC07-03
9. รันทดสอบตาม AC-SUM-01 ถึง AC-SUM-04 และบันทึกผลที่ยังติด Q-01 ถึง Q-03

## 8. สิ่งที่ยังไม่ทำ

- Q-01 การ “สรุปงบ” โดยเหรัญญิกทำผ่าน use case ใด และอยู่ในระบบหรือนอกระบบ: ส่วนเชื่อมต่อและแหล่งข้อมูลสถานะงบจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-02 รูปแบบหรือเทมเพลตของเล่มสรุปโครงการเป็นประเภทไฟล์และโครงสร้างใด: การตรวจประเภทไฟล์และโครงสร้างเอกสารจะยังไม่สร้างจนกว่าจะได้คำตอบ
- Q-03 หากอัปโหลดผิดไฟล์หรือไม่ครบ จะอัปโหลดใหม่ทับได้หรือไม่: พฤติกรรมการแก้ไขและอัปโหลดทับจะยังไม่สร้างจนกว่าจะได้คำตอบ
