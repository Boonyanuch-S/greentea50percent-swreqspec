# Feature: ส่งอีเมลแจ้งเตือน (Send Email Notification)
Spec ID: SPEC-NOTI-010 | Source: UC-10 (Use Case Table) | Use case: UC-10
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-19

## Goal
ระบบส่งอีเมลแจ้งเตือนอัตโนมัติไปยังผู้เกี่ยวข้อง เมื่อเกิดเหตุการณ์สำคัญในกระบวนการ
(เช่น อนุมัติเอกสาร, ตีกลับ, บันทึกชั่วโมงสำเร็จ) โดยไม่ทำให้เหตุการณ์ต้นทางล้มเหลว
หากการส่งอีเมลไม่สำเร็จ ฟีเจอร์นี้ถูกเรียกใช้เป็น service ภายในจาก use case อื่นเท่านั้น
ไม่มีผู้ใช้กดเรียกเอง (Primary Actor = ระบบ)

## Scope
### In scope
- รับคำขอจาก use case ต้นทาง (เช่น UC-05, UC-07) พร้อมประเภทเหตุการณ์และผู้รับ
- สร้างเนื้อหาอีเมลตาม template ของเหตุการณ์นั้น
- ส่งอีเมลผ่านบริการอีเมลภายนอก (เช่น Amazon SES)
- บันทึก log การส่งทุกครั้ง
- เข้าคิวส่งซ้ำอัตโนมัติเมื่อส่งไม่สำเร็จ โดยไม่ทำให้ transaction ของเหตุการณ์ต้นทางล้มเหลว
### Out of scope
- การกำหนด/แก้ไข template เนื้อหาอีเมลของแต่ละเหตุการณ์ (ที่มา/เจ้าของ template ยังไม่ระบุ - ดู Q-03)
- การตั้งค่าบัญชีอีเมลผู้รับ (สมมติว่าลงทะเบียนไว้แล้วในระบบ - precondition)
- ช่องทางแจ้งเตือนอื่นนอกจากอีเมล (เช่น in-app notification ตาม NFR ข้อ 22 ใน UC-09, SMS/LINE)
  - เป็นฟีเจอร์แยกต่างหาก

## Constraints
- IF-EMAIL-01 ระบบต้องส่งอีเมลผ่านบริการอีเมลภายนอก (เช่น Amazon SES)
- IF-CALL-01 ฟีเจอร์นี้ถูกเรียกใช้จาก use case อื่นเท่านั้น (internal call) ไม่มีหน้าจอผู้ใช้ของตัวเอง
- NFR-REL-01 ระบบต้องเข้าคิวส่งซ้ำอัตโนมัติเมื่อส่งอีเมลไม่สำเร็จ ตามที่กำหนดไว้ใน
  Infrastructure Requirements (รายละเอียดจำนวนครั้ง/ระยะเวลาส่งซ้ำยังไม่ระบุในตารางนี้ - ดู Q-01)

## Requirements
- FR-NOTI-01 ระบบต้องรับคำขอจาก use case ต้นทาง พร้อมประเภทเหตุการณ์และผู้รับ เพื่อเริ่มกระบวนการแจ้งเตือน
                                                                        <- UC-10 Main Flow ขั้น 1
- FR-NOTI-02 ระบบต้องสร้างเนื้อหาอีเมลตาม template ที่ตรงกับประเภทเหตุการณ์นั้น
                                                                        <- UC-10 Main Flow ขั้น 2
- FR-NOTI-03 ระบบต้องส่งอีเมลผ่านบริการอีเมลภายนอก (เช่น Amazon SES) ไปยังผู้รับที่ระบุ
                                                                        <- UC-10 Main Flow ขั้น 3
- FR-NOTI-04 ระบบต้องบันทึก log การส่งอีเมลทุกครั้ง ไม่ว่าจะสำเร็จหรือไม่สำเร็จ
                                                                        <- UC-10 Main Flow ขั้น 4
- FR-NOTI-05 หากส่งอีเมลไม่สำเร็จ ระบบต้องเข้าคิวส่งซ้ำอัตโนมัติ โดยต้องไม่ทำให้ transaction/เหตุการณ์
  ต้นทาง (เช่น การอนุมัติ) ล้มเหลวตามไปด้วย                                  <- UC-10 Exception Flow 3a

## Quality Requirements
- NFR-REL-01 (อ้างอิง NFR-REL ใน Infrastructure Requirements) ระบบต้องเข้าคิวส่งซ้ำอัตโนมัติ
  เมื่อส่งอีเมลไม่สำเร็จ ตามนโยบายที่กำหนดไว้ (ยังไม่ทราบตัวเลขจำนวนครั้ง/ช่วงเวลา - ดู Q-01)

## Acceptance Criteria
- [ ] AC-NOTI-01 (FR-NOTI-03)
      Given เกิดเหตุการณ์ที่ต้องแจ้งเตือนและผู้รับมีอีเมลถูกต้อง
      When  ระบบเรียก UC-10
      Then  อีเมลต้องถูกส่งถึงผู้รับภายในเวลาที่กำหนด
- [ ] AC-NOTI-02 (FR-NOTI-05)
      Given บริการอีเมลล้มเหลวชั่วคราว
      When  ระบบพยายามส่ง
      Then  ระบบต้องเข้าคิวส่งซ้ำ ไม่ทำให้เหตุการณ์ต้นทางล้มเหลวตามไปด้วย
- [ ] AC-NOTI-03 (FR-NOTI-02)
      Given มีคำขอแจ้งเตือนสำหรับเหตุการณ์ประเภทหนึ่ง (เช่น อนุมัติเอกสาร)
      When  ระบบสร้างเนื้อหาอีเมล
      Then  เนื้อหาที่สร้างตรงตาม template ของเหตุการณ์ประเภทนั้น
- [ ] AC-NOTI-04 (FR-NOTI-04)
      Given ระบบพยายามส่งอีเมล ไม่ว่าจะสำเร็จหรือไม่สำเร็จ
      When  กระบวนการส่งเสร็จสิ้น
      Then  มี log บันทึกผลการส่งไว้เสมอ

## Assumptions & Open Questions
- ASM-01 ข้อความในแถว Stakeholder & Interest ของภาพต้นฉบับอ่านไม่ชัดเจนในบางจุด สรุปความโดยรวมว่า
  ผู้มีส่วนเกี่ยวข้อง (อาจารย์, กรรมการสโมสร, นักศึกษาที่เข้าร่วม) ต้องการทราบผลลัพธ์ของกระบวนการ
  (อนุมัติ/ตีกลับ/บันทึกชั่วโมงสำเร็จ) อย่างรวดเร็วโดยไม่ต้องรอกระดาษหรือถามเอง -> ดู Q-04
- Q-01 "ตามที่กำหนดไว้ใน Infrastructure Requirements" (NFR-REL) หมายถึงเอกสารข้อกำหนดชุดใด
  และมีตัวเลขจำนวนครั้ง/ช่วงเวลาส่งซ้ำเท่าไร? ไม่มีรายละเอียดอยู่ในตารางนี้
- Q-02 "เวลาที่กำหนด" ใน AC-NOTI-01 (อีเมลต้องถูกส่งถึงผู้รับภายในเวลาที่กำหนด) ไม่มีตัวเลขระบุ
  -> ต้องการ SLA ที่ชัดเจน (เช่น กี่นาที) เพื่อให้ทดสอบได้จริง
- Q-03 Trigger ในตารางระบุว่ามี "10 กรณีที่กำหนดไว้" แต่ในตารางให้ตัวอย่างเพียง 2 กรณี (UC-05 อนุมัติเสร็จ,
  UC-07 บันทึกชั่วโมงสำเร็จ) -> ต้องการรายการครบทั้ง 10 กรณี พร้อม template ของแต่ละกรณี
  เพื่อออกแบบ FR-NOTI-02 ให้ครบถ้วน
- Q-04 ขอภาพต้นฉบับที่ชัดกว่านี้ของแถว Stakeholder & Interest เพื่อยืนยันถ้อยคำที่แน่นอน
