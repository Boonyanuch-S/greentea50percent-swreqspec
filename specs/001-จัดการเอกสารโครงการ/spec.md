## Goal
กรรมการสโมสรนักศึกษาสร้างหรือแก้ไขเอกสารโครงการกิจกรรม กรอกข้อมูลหลักและแนบเอกสารประกอบ
ให้ครบตามเกณฑ์ (Checklist) แล้วส่งเข้าสู่คิวตรวจสอบของเจ้าหน้าที่คณะ เพื่อให้เอกสารทุกโครงการ
มีมาตรฐานเดียวกัน และไม่ต้องแก้ไขเอกสารซ้ำภายหลัง

## Scope
### In scope
- สร้างเอกสารโครงการใหม่ (แสดงฟอร์มเอกสารเปล่าให้กรอก)
- กรอกข้อมูลโครงการ: ชื่อโครงการ วัตถุประสงค์ วันที่ สถานที่ และตัวชี้วัด
- แสดง Checklist เอกสารที่ต้องแนบตามเกณฑ์ที่กำหนด ก่อนอนุญาตให้ส่ง
- แนบเอกสารประกอบตามที่ระบุใน Checklist
- ตรวจสอบความครบถ้วนของเอกสารแนบก่อนบันทึก/ส่ง
- บันทึกเอกสารโครงการเข้าสู่คิวของเจ้าหน้าที่คณะ และเปลี่ยนสถานะเป็น "รอเจ้าหน้าที่คณะตรวจสอบ"
- แก้ไขโครงการที่เคยถูกตีกลับ โดยโหลดข้อมูลเดิมพร้อมเหตุผลที่ถูกตีกลับ
### Out of scope
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- การตรวจสอบเอกสารโดยเจ้าหน้าที่คณะหลังเข้าคิว (use case ฝั่งเจ้าหน้าที่ เช่น UC-07/UC-08)
- การกำหนด/ดูแลเกณฑ์ Checklist เอง (owner ของเกณฑ์ยังไม่ระบุในตาราง - ดู Q-01)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login, UC-09) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-CHK-01 ระบบต้องอ้างอิงเกณฑ์ Checklist เอกสารแนบที่กำหนดไว้ในระบบ (ที่มาของเกณฑ์ยังไม่ระบุในตาราง)

## Requirements
- FR-PRJ-01 เมื่อกรรมการสโมสรเลือก "สร้างโครงการใหม่" ระบบต้องแสดงฟอร์มเอกสารเปล่าให้กรอก <- UC-01 Main Flow ขั้น 1-2
- FR-PRJ-02 ระบบต้องให้กรรมการกรอกข้อมูลโครงการ: ชื่อโครงการ วัตถุประสงค์ วันที่ สถานที่ และตัวชี้วัด
                                                                        <- UC-01 Main Flow ขั้น 3
- FR-PRJ-03 ระบบต้องแสดง Checklist เอกสารที่ต้องแนบตามเกณฑ์ที่กำหนด ก่อนกรรมการกดส่ง
                                                                        <- UC-01 Main Flow ขั้น 4
- FR-PRJ-04 ระบบต้องให้กรรมการแนบเอกสารประกอบตามที่ระบุใน Checklist (เช่น กส 002)
                                                                        <- UC-01 Main Flow ขั้น 5
- FR-PRJ-05 เมื่อกรรมการกดส่ง และเอกสารแนบครบตาม Checklist ระบบต้องบันทึกเอกสารโครงการ
  เข้าสู่คิวของเจ้าหน้าที่คณะ และเปลี่ยนสถานะเป็น "รอเจ้าหน้าที่คณะตรวจสอบ"     <- UC-01 Main Flow ขั้น 6-7 / Postcondition
- FR-PRJ-06 เมื่อกรรมการแก้ไขโครงการที่เคยถูกตีกลับ ระบบต้องโหลดข้อมูลเดิมของโครงการนั้น
  พร้อมแสดงเหตุผลที่เจ้าหน้าที่ตีกลับ แล้วพากรรมการกลับไปยังขั้นกรอกข้อมูล (ขั้นที่ 3)
                                                                        <- UC-01 Alternative Flow 3a
- FR-PRJ-07 หากเอกสารแนบไม่ครบตาม Checklist ระบบต้องปฏิเสธการส่ง และแสดงรายการเอกสารที่ยังขาด
  ให้กรรมการไปแก้ไข โดยไม่บันทึกหรือเปลี่ยนสถานะโครงการ                    <- UC-01 Exception Flow 4a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์สร้าง/แก้ไขเอกสารโครงการ ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-PRJ-01 (FR-PRJ-05)
      Given กรรมการกรอกข้อมูลโครงการครบถ้วนตามฟอร์ม และแนบเอกสารครบตาม Checklist
      When  กรรมการกดส่ง
      Then  ระบบบันทึกเอกสารโครงการ และเปลี่ยนสถานะเป็น "รอเจ้าหน้าที่คณะตรวจสอบ"
- [ ] AC-PRJ-02 (FR-PRJ-07)
      Given เอกสารแนบขาดอย่างน้อย 1 รายการตาม Checklist
      When  กรรมการกดส่ง
      Then  ระบบปฏิเสธการส่ง และแสดงรายการเอกสารที่ยังไม่ครบ โดยไม่บันทึกเอกสารเข้าสู่คิว
- [ ] AC-PRJ-03 (FR-PRJ-01)
      Given กรรมการสโมสรเลือก "สร้างโครงการใหม่"
      When  ระบบโหลดหน้าจอ
      Then  ระบบแสดงฟอร์มเอกสารเปล่าพร้อมให้กรอกข้อมูล
- [ ] AC-PRJ-04 (FR-PRJ-03)
      Given กรรมการกรอกข้อมูลโครงการครบตามฟอร์มแล้ว
      When  ระบบแสดงหน้าแนบเอกสาร
      Then  ระบบแสดง Checklist เอกสารที่ต้องแนบตามเกณฑ์ที่กำหนดของกิจกรรมนั้น
- [ ] AC-PRJ-05 (FR-PRJ-06)
      Given กรรมการเปิดโครงการที่เคยถูกตีกลับเพื่อแก้ไข
      When  ระบบโหลดโครงการนั้น
      Then  ระบบแสดงข้อมูลเดิมของโครงการ พร้อมเหตุผลที่เจ้าหน้าที่ตีกลับ และพากรรมการไปยังขั้นกรอกข้อมูล
- [ ] AC-PRJ-06 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์สร้าง/แก้ไขเอกสารโครงการ
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ
