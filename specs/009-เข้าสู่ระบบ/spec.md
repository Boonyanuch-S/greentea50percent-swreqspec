# Feature: เข้าสู่ระบบ (Login)
Spec ID: SPEC-AUTH-009 | Source: UC-09 (Use Case Table) | Use case: UC-09
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-20

## Goal
ผู้ใช้งานทุกบทบาท (กรรมการสโมสร, เจ้าหน้าที่คณะ, อาจารย์ที่ปรึกษา, เจ้าหน้าที่กองกิจ) เข้าสู่ระบบ
ด้วยบัญชีผู้ใช้ ระบบตรวจสอบความถูกต้องและออก Token สำหรับเข้าถึงฟังก์ชันตามบทบาท (RBAC)
เพื่อให้แต่ละบทบาทเข้าถึงได้เฉพาะฟังก์ชันของตน และควบคุมการเข้าถึงข้อมูลนักศึกษาให้สอดคล้องกับ PDPA

## Scope
### In scope
- แสดงหน้าเข้าสู่ระบบ เมื่อผู้ใช้เปิดระบบครั้งแรกหรือ Token หมดอายุ
- รับบัญชีผู้ใช้และรหัสผ่าน และตรวจสอบความถูกต้องผ่าน Login API
- ออก Token และนำผู้ใช้เข้าสู่หน้าจอตามบทบาทของตน (RBAC) เมื่อเข้าสู่ระบบสำเร็จ
- ปฏิเสธการเข้าสู่ระบบด้วยข้อความทั่วไปเมื่อบัญชีหรือรหัสผ่านไม่ถูกต้อง (ไม่ระบุว่าผิดที่จุดใด)
- บังคับให้เข้าสู่ระบบใหม่เมื่อ Token หมดอายุ
### Out of scope
- การสร้าง/ลงทะเบียนบัญชีผู้ใช้ใหม่ (precondition ของฟีเจอร์นี้คือ "มีบัญชีผู้ใช้ในระบบแล้ว")
- การกำหนดสิทธิ์ RBAC ของแต่ละบทบาทเอง (ฟีเจอร์นี้เพียงใช้สิทธิ์ RBAC ที่กำหนดไว้แล้วมาออก Token)
- เนื้อหา/กลไกการแจ้งเตือนแบบ in-app ตามบทบาท (NFR ข้อ 22) - ฟีเจอร์นี้เพียงทำให้ระบบทราบบทบาท
  ของผู้ใช้หลัง login เท่านั้น (ดู Q-03)
- การลืมรหัสผ่าน / รีเซ็ตรหัสผ่าน (ไม่ได้ระบุใน use case นี้)

## Constraints
- DOM-PDPA-02 ระบบต้องควบคุมการเข้าถึงข้อมูลนักศึกษาตามบทบาท (RBAC) เพื่อให้สอดคล้องกับ PDPA
- SEC-AUTHMSG-01 ข้อความแจ้งเตือนเมื่อเข้าสู่ระบบไม่สำเร็จ ต้องเป็นข้อความทั่วไปเดียว
  ("บัญชีหรือรหัสผ่านไม่ถูกต้อง") ไม่ระบุว่าผิดที่บัญชีหรือรหัสผ่าน (ป้องกันการเดา/user enumeration)
- IF-TOKEN-01 ระบบต้องออก Token ที่มีวันหมดอายุ และบังคับให้เข้าสู่ระบบใหม่เมื่อ Token หมดอายุ

## Requirements
- FR-AUTH-01 ระบบต้องแสดงหน้าเข้าสู่ระบบ เมื่อผู้ใช้เปิดระบบครั้งแรก หรือเมื่อ Token หมดอายุ
                                                                        <- UC-09 Trigger / Main Flow ขั้น 1
- FR-AUTH-02 ระบบต้องให้ผู้ใช้กรอกบัญชีผู้ใช้และรหัสผ่าน
                                                                        <- UC-09 Main Flow ขั้น 2
- FR-AUTH-03 ระบบต้องตรวจสอบความถูกต้องของบัญชีและรหัสผ่านผ่าน Login API หาก Login API ไม่ตอบสนองหรือเกิดข้อผิดพลาด
  ระบบต้องแจ้งว่า "เกิดข้อผิดพลาดกรุณาลองใหม่อีกครั้ง" และให้ผู้ใช้อยู่ที่หน้า login
                                                                        <- UC-09 Main Flow ขั้น 3
- FR-AUTH-04 เมื่อบัญชีและรหัสผ่านถูกต้อง ระบบต้องออก Token และนำผู้ใช้เข้าสู่หน้าจอตามบทบาทของตน (RBAC)
                                                                        <- UC-09 Main Flow ขั้น 4 / Postcondition
- FR-AUTH-05 หากบัญชีหรือรหัสผ่านไม่ถูกต้อง ระบบต้องปฏิเสธการเข้าสู่ระบบ แสดงข้อความทั่วไปว่า
  "บัญชีหรือรหัสผ่านไม่ถูกต้อง" โดยไม่ระบุว่าผิดที่จุดใด และวนกลับไปหน้าเข้าสู่ระบบ
                                                                        <- UC-09 Exception Flow 3a

## Quality Requirements
- NFR-SEC-02 (อ้างอิง NFR ข้อ 22) ระบบต้องทราบบทบาทของผู้ใช้จากการ login สำเร็จ ก่อนจึงจะกำหนดสิทธิ์
  การแจ้งเตือนแบบ in-app เฉพาะบางบทบาทได้ (ความสัมพันธ์โดยตรงกับฟีเจอร์นี้ยังไม่ชัดเจนทั้งหมด - ดู Q-03)

## Acceptance Criteria
- [ ] AC-AUTH-01 (FR-AUTH-04)
      Given บัญชีและรหัสผ่านถูกต้อง
      When  ผู้ใช้กดเข้าสู่ระบบ
      Then  ระบบออก Token และนำเข้าสู่หน้าจอตามบทบาทถูกต้อง
- [ ] AC-AUTH-02 (FR-AUTH-05)
      Given รหัสผ่านไม่ถูกต้อง
      When  ผู้ใช้กดเข้าสู่ระบบ
      Then  ระบบปฏิเสธและแสดงข้อความทั่วไปว่า "บัญชีหรือรหัสผ่านไม่ถูกต้อง"
- [ ] AC-AUTH-03 (FR-AUTH-05)
      Given บัญชีผู้ใช้ไม่มีอยู่ในระบบ (username ไม่ถูกต้อง)
      When  ผู้ใช้กดเข้าสู่ระบบ
      Then  ระบบแสดงข้อความทั่วไปเดียวกันว่า "บัญชีหรือรหัสผ่านไม่ถูกต้อง" โดยไม่เปิดเผยว่าบัญชีไม่มีอยู่จริง
- [ ] AC-AUTH-04 (FR-AUTH-01)
      Given Token ของผู้ใช้หมดอายุระหว่างใช้งาน
      When  ผู้ใช้พยายามเข้าถึงฟังก์ชันใด ๆ ในระบบ
      Then  ระบบแสดงหน้าต่างแจ้งว่า Token หมดอายุ และพาผู้ใช้กลับไปยังหน้าเข้าสู่ระบบทันที

## Assumptions & Open Questions
- ASM-01 "บทบาทของตน (RBAC)" ครอบคลุม 4 บทบาทหลักตามตาราง: กรรมการสโมสร, เจ้าหน้าที่คณะ,
  อาจารย์ที่ปรึกษา, เจ้าหน้าที่กองกิจ ซึ่งตรงกับ Primary Actor ของ UC-01 ถึง UC-08 ที่ทำสเปกไปก่อนหน้านี้
- ASM-02 Token มีอายุ 30 นาที เมื่อหมดอายุระบบจะแสดงหน้าต่างแจ้งเตือนและพาผู้ใช้กลับไปยังหน้า login ทันที
- ASM-03 ผู้ใช้แต่ละบทบาทมีหน้าหลักแตกต่างกันหลัง login สำเร็จ
- ASM-04 เมื่อ Login API ไม่ตอบสนองหรือเกิดข้อผิดพลาด ระบบจะแจ้งว่า "เกิดข้อผิดพลาดกรุณาลองใหม่อีกครั้ง"
- Q-01 ต้องกำหนดชื่อหรือเส้นทางหน้าหลักของกรรมการสโมสร เจ้าหน้าที่คณะ อาจารย์ที่ปรึกษา และเจ้าหน้าที่กองกิจอย่างไร?
  เกี่ยวกับ FR-AUTH-04, AC-AUTH-01
- Q-02 เมื่อเปิดระบบครั้งแรกโดยยังไม่มี Token ต้องแสดงหน้า login ทันทีหรือมีหน้าต่างแจ้งเตือนร่วมด้วย?
  เกี่ยวกับ FR-AUTH-01
- Q-03 Token ไม่ถูกต้องหรือถูกยกเลิก ต้องจัดการเหมือน Token หมดอายุหรือไม่?
  เกี่ยวกับ IF-TOKEN-01, FR-AUTH-01, AC-AUTH-04
- Q-04 NFR-SEC-02 เป็นข้อกำหนดของฟีเจอร์ login โดยตรง หรือให้ฟีเจอร์การแจ้งเตือนเป็นผู้รับผิดชอบ โดย login เพียงส่งต่อบทบาท?
  เกี่ยวกับ NFR-SEC-02
- Q-05 ต้องจำกัดจำนวนครั้งที่กรอกรหัสผ่านผิดหรือล็อกบัญชีชั่วคราวหรือไม่?
  เกี่ยวกับ Q-02 เดิม
- Q-06 อนุญาตให้บัญชีเดียวกัน login หลายอุปกรณ์หรือหลาย session พร้อมกันหรือไม่ และต้องรองรับ remember me หรือ refresh token หรือไม่?
  เกี่ยวกับ Q-04 และ Q-05 เดิม
