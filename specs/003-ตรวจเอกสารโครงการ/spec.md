## Goal
เจ้าหน้าที่คณะวิทยาศาสตร์ตรวจสอบความถูกต้องของเอกสารโครงการที่สโมสรส่งเข้าคิว (จาก UC-01)
โดยเจ้าหน้าที่เลือกทำเครื่องหมายรายการเอกสารจาก Checklist ส่วนกลางที่เกี่ยวข้องกับแต่ละโครงการได้
โดยไม่มีชุดเอกสารหรือชื่อเรียกตายตัว เจ้าหน้าที่คณะทุกคนร่วมกันเพิ่มหรือแก้ไขรายการส่วนกลางได้
ระบบแสดง Checklist ส่วนกลางฉบับล่าสุดชุดเดียวกันแก่เจ้าหน้าที่ทุกคน ก่อนอนุมัติส่งต่อให้อาจารย์ที่ปรึกษา
หรือตีกลับพร้อมเหตุผล เพื่อให้กรรมการสโมสรทราบเหตุผลที่ชัดเจนเมื่อเอกสารถูกตีกลับ

## Scope
### In scope
- แสดงคิวเอกสารโครงการที่รอตรวจสอบ เรียงตามวันที่ส่งเข้าก่อน-หลัง
- เปิดดูรายละเอียดโครงการแต่ละฉบับ
- เลือกทำเครื่องหมายรายการเอกสารจาก Checklist ส่วนกลางให้เหมาะกับโครงการแต่ละฉบับ โดยไม่บังคับชุดเอกสารหรือชื่อเรียกตายตัว
- ตรวจและทำเครื่องหมายรายการเอกสารที่เกี่ยวข้องว่าครบหรือไม่ครบ
- เพิ่มหรือแก้ไขรายการและชื่อเอกสารใน Checklist ส่วนกลางโดยเจ้าหน้าที่คณะ
- ให้เจ้าหน้าที่ตรวจสอบเนื้อหาและรูปแบบเอกสาร
- อนุมัติและส่งต่อเอกสารให้อาจารย์ที่ปรึกษา (เชื่อม UC-05) พร้อมแจ้งกรรมการสโมสรว่าอนุมัติแล้ว
- ตีกลับเอกสารพร้อมระบุเหตุผล และแจ้งกรรมการสโมสร (ย้อนกลับ UC-01)
- ให้เจ้าหน้าที่ทุกคนใช้ Checklist ส่วนกลางฉบับล่าสุดชุดเดียวกัน แม้ชุดรายการที่เลือกใช้กับแต่ละโครงการจะแตกต่างกัน
### Out of scope
- การส่งเอกสารโครงการเข้าคิว (UC-01) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition/trigger)
- การตรวจสอบโดยอาจารย์ที่ปรึกษาหลังส่งต่อ (UC-05)
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-CHK-02 ระบบต้องอ้างอิงเกณฑ์ Checklist กลางฉบับล่าสุดเสมอ ไม่ให้เจ้าหน้าที่แต่ละคนตรวจด้วยเกณฑ์เวอร์ชันต่างกัน
- IF-UC05-01 เมื่ออนุมัติ ระบบต้องส่งต่อเอกสารเข้าสู่คิวของ UC-05 (อาจารย์ที่ปรึกษา)
- IF-UC01-01 เมื่อตีกลับ ระบบต้องแจ้งกรรมการสโมสรผ่านทาง UC-01 พร้อมเหตุผลที่ระบุ

## Requirements
- FR-VDC-01 ระบบต้องแสดงคิวเอกสารโครงการที่รอตรวจสอบ เรียงตามวันที่ส่งเข้าก่อน-หลัง
                                                                        <- UC-03 Main Flow ขั้น 1
- FR-VDC-02 ระบบต้องให้เจ้าหน้าที่เปิดดูรายละเอียดของโครงการที่เลือกได้
                                                                        <- UC-03 Main Flow ขั้น 2
- FR-VDC-03 ระบบต้องให้เจ้าหน้าที่เลือกทำเครื่องหมายรายการเอกสารที่เกี่ยวข้องกับโครงการแต่ละฉบับจาก Checklist ส่วนกลาง
  และแสดงสถานะครบ/ไม่ครบของรายการที่เลือก โดยไม่บังคับให้ทุกโครงการใช้ชุดเอกสารหรือชื่อเรียกเดียวกัน
                                                                        <- UC-03 Main Flow ขั้น 3
- FR-VDC-04 ระบบต้องให้เจ้าหน้าที่ตรวจสอบเนื้อหาและรูปแบบเอกสารก่อนตัดสินใจ
                                                                        <- UC-03 Main Flow ขั้น 4
- FR-VDC-05 เมื่อเจ้าหน้าที่กดอนุมัติ ระบบต้องส่งเอกสารต่อให้อาจารย์ที่ปรึกษา (เชื่อม UC-05)
  เปลี่ยนสถานะเอกสารเป็น "ส่งต่ออาจารย์" และแจ้งกรรมการสโมสรว่าอนุมัติแล้ว        <- UC-03 Main Flow ขั้น 5 / Postcondition
- FR-VDC-06 เมื่อเจ้าหน้าที่พบว่าเอกสารไม่ครบ และกดตีกลับพร้อมระบุเหตุผล ระบบต้องเปลี่ยนสถานะ
  เอกสารเป็น "ตีกลับให้แก้ไข" และแจ้งกรรมการสโมสรพร้อมเหตุผลที่ระบุ (ย้อนกลับ UC-01)  <- UC-03 Alternative Flow 4a
- FR-VDC-07 ระบบต้องยึดเกณฑ์ Checklist กลางฉบับล่าสุดเป็นหลักเสมอสำหรับเจ้าหน้าที่ทุกคน
  โดยเจ้าหน้าที่คณะทุกคนสามารถเพิ่มหรือแก้ไขรายการและชื่อเอกสารใน Checklist ส่วนกลางได้ และทุกคนเห็นรายการส่วนกลางฉบับเดียวกัน
  เจ้าหน้าที่เลือกทำเครื่องหมายรายการที่ใช้ตรวจได้แตกต่างกันในแต่ละโครงการ       <- UC-03 Exception Flow 5a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงคิวและรายละเอียดเอกสารโครงการ ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-VDC-01 (FR-VDC-05)
      Given เอกสารครบตาม Checklist กลาง
      When  เจ้าหน้าที่กดอนุมัติ
      Then  ระบบส่งต่อให้อาจารย์ที่ปรึกษา และแจ้งกรรมการสโมสรว่าอนุมัติแล้ว
- [ ] AC-VDC-02 (FR-VDC-06)
      Given เอกสารไม่ครบตาม Checklist
      When  เจ้าหน้าที่กดตีกลับพร้อมเหตุผล
      Then  ระบบแจ้งกรรมการสโมสรพร้อมเหตุผลที่ระบุ
- [ ] AC-VDC-03 (FR-VDC-01)
      Given มีเอกสารโครงการหลายฉบับรอตรวจสอบ
      When  เจ้าหน้าที่เปิดคิวเอกสาร
      Then  ระบบแสดงลิสต์เรียงตามวันที่ส่งเข้าก่อน-หลัง
- [ ] AC-VDC-04 (FR-VDC-03)
      Given เจ้าหน้าที่เปิดดูรายละเอียดโครงการหนึ่งและมี Checklist ส่วนกลาง
      When  เจ้าหน้าที่ทำเครื่องหมายเลือกรายการเอกสารที่เกี่ยวข้องกับโครงการนั้น
      Then  ระบบแสดงรายการที่เลือกและสถานะครบ/ไม่ครบ โดยไม่บังคับชุดเอกสารหรือชื่อเรียกเดียวกันทุกโครงการ
- [ ] AC-VDC-05 (FR-VDC-07)
      Given เจ้าหน้าที่คณะคนหนึ่งเพิ่มหรือแก้ไขรายการใน Checklist ส่วนกลาง
      When  เจ้าหน้าที่คณะอีกคนเปิด Checklist ส่วนกลาง
      Then  ทั้งสองคนเห็นรายการส่วนกลางฉบับล่าสุดชุดเดียวกัน และผู้ตรวจสามารถทำเครื่องหมายเลือกรายการที่เกี่ยวข้องกับโครงการของตนได้
- [ ] AC-VDC-06 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงคิวหรือรายละเอียดเอกสารโครงการ
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 Checklist ส่วนกลางเป็นรายการเอกสารที่เจ้าหน้าที่คณะทุกคนร่วมกันเพิ่มหรือแก้ไขได้
  เจ้าหน้าที่ผู้ตรวจทำเครื่องหมายเลือกเฉพาะรายการที่เกี่ยวข้องกับแต่ละโครงการ โดยไม่บังคับรูปแบบ ชุดเอกสาร
  หรือชื่อเรียกตายตัว
- ASM-02 ตามคำยืนยันของทีม ข้อความ Exception Flow 5a หมายถึงกรณีเจ้าหน้าที่อาจเห็น Checklist คนละเวอร์ชัน
  ระบบจึงต้องให้ทุกคนเห็นรายการส่วนกลางฉบับล่าสุดชุดเดียวกัน
- ASM-03 เมื่อเจ้าหน้าที่แก้ไขรายการ Checklist การแก้ไขมีผลทันทีต่อเอกสารที่กำลังตรวจ
  สถานะตรวจที่ผูกกับรายการเดิมคงอยู่ตราบใดที่รายการนั้นยังอยู่ใน Checklist
- Q-01 (ตอบแล้ว 2569-10-30) เจ้าหน้าที่คณะทุกคนเพิ่มหรือแก้ไขรายการใน Checklist ส่วนกลางได้
  และผู้ตรวจทำเครื่องหมายเลือกรายการที่เกี่ยวข้องกับแต่ละโครงการเอง โดยไม่กำหนดชุดเอกสารหรือชื่อเรียกตายตัว
  แหล่งอ้างอิงที่ทีมให้: https://dsa.su.ac.th/ksu/?page_id=306
  (ใช้เป็นข้อมูลอ้างอิง ไม่ได้นำชื่อเอกสารจากแหล่งนี้มากำหนดเป็นรายการตายตัว)
- Q-02 (ตอบแล้ว 2569-10-30) ข้อความ Exception Flow 5a หมายถึงเมื่อ Checklist ส่วนกลางมีการเปลี่ยนแปลง
  เจ้าหน้าที่ทุกคนต้องเห็นรายการส่วนกลางฉบับล่าสุดชุดเดียวกัน; รายการที่เลือกใช้ในแต่ละโครงการอาจแตกต่างกัน
- Q-07 (ตอบแล้ว 2569-10-30) เมื่อแก้ไข Checklist ให้มีผลทันทีต่อเอกสารที่กำลังตรวจ
  และคงสถานะตรวจเดิมไว้ตราบใดที่รายการเดิมยังอยู่ใน Checklist
- Q-03 (ตอบแล้ว 2569-10-30) การแจ้งกรรมการสโมสรเมื่ออนุมัติ (AC-VDC-01) ให้ทำแบบ synchronous
- Q-04 (ตอบแล้ว 2569-10-30) เมื่อตีกลับ ให้กรรมการแก้ไขเฉพาะจุดที่ระบุในเหตุผลได้ โดยไม่ต้องกรอกเอกสารทั้งฉบับใหม่
- Q-05 (ตอบแล้ว 2569-10-30) หากมีคำตัดสินซ้ำต่อเอกสารเดียวกัน ให้คำตัดสินล่าสุดแทนที่คำตัดสินก่อนหน้า
- Q-06 (ตอบแล้ว 2569-10-30) หากวันเวลาส่งเท่ากัน ให้เรียง `submission_id` จากน้อยไปมาก
