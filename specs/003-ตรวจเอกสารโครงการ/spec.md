## Goal
เจ้าหน้าที่คณะวิทยาศาสตร์ตรวจสอบความถูกต้องของเอกสารโครงการที่สโมสรส่งเข้าคิว (จาก UC-01)
เทียบกับ Checklist เกณฑ์กลางฉบับล่าสุด แล้วอนุมัติส่งต่อให้อาจารย์ที่ปรึกษา หรือตีกลับพร้อมเหตุผล
เพื่อให้เจ้าหน้าที่ทุกคนใช้เกณฑ์เดียวกัน และกรรมการสโมสรทราบเหตุผลที่ชัดเจนเมื่อถูกตีกลับ

## Scope
### In scope
- แสดงคิวเอกสารโครงการที่รอตรวจสอบ เรียงตามวันที่ส่งเข้าก่อน-หลัง
- เปิดดูรายละเอียดโครงการแต่ละฉบับ
- แสดง Checklist ความครบถ้วนของเอกสารตามเกณฑ์กลางฉบับล่าสุด
- ให้เจ้าหน้าที่ตรวจสอบเนื้อหาและรูปแบบเอกสาร
- อนุมัติและส่งต่อเอกสารให้อาจารย์ที่ปรึกษา (เชื่อม UC-05) พร้อมแจ้งกรรมการสโมสรว่าอนุมัติแล้ว
- ตีกลับเอกสารพร้อมระบุเหตุผล และแจ้งกรรมการสโมสร (ย้อนกลับ UC-01)
- บังคับใช้เกณฑ์ Checklist กลางฉบับล่าสุดเป็นมาตรฐานเดียวสำหรับเจ้าหน้าที่ทุกคน
### Out of scope
- การส่งเอกสารโครงการเข้าคิว (UC-01) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition/trigger)
- การตรวจสอบโดยอาจารย์ที่ปรึกษาหลังส่งต่อ (UC-05)
- การกำหนด/ปรับปรุงเกณฑ์ Checklist กลางเอง (owner ของเกณฑ์ยังไม่ระบุในตาราง - ดู Q-01)
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-CHK-02 ระบบต้องอ้างอิงเกณฑ์ Checklist กลางฉบับล่าสุดเสมอ ไม่ให้เจ้าหน้าที่แต่ละคนตรวจด้วยเกณฑ์เวอร์ชันต่างกัน
- IF-UC05-01 เมื่ออนุมัติ ระบบต้องส่งต่อเอกสารเข้าสู่คิวของ UC-05 (อาจารย์ที่ปรึกษา)
- IF-UC01-01 เมื่อตีกลับ ระบบต้องแจ้งกรรมการสโมสรผ่านทาง UC-01 พร้อมเหตุผลที่ระบุ

## Requirements
- FR-VDC-01 ระบบต้องแสดงคิวเอกสารโครงการที่รอตรวจสอบ เรียงตามวันที่ส่งเข้าก่อน-หลัง
                                                                        <- UC-03 Main Flow ขั้น 1
- FR-VDC-02 ระบบต้องให้เจ้าหน้าที่เปิดดูรายละเอียดของโครงการที่เลือกได้
                                                                        <- UC-03 Main Flow ขั้น 2
- FR-VDC-03 ระบบต้องแสดง Checklist ว่าเอกสารครบตามเกณฑ์กลางฉบับล่าสุดหรือไม่
                                                                        <- UC-03 Main Flow ขั้น 3
- FR-VDC-04 ระบบต้องให้เจ้าหน้าที่ตรวจสอบเนื้อหาและรูปแบบเอกสารก่อนตัดสินใจ
                                                                        <- UC-03 Main Flow ขั้น 4
- FR-VDC-05 เมื่อเจ้าหน้าที่กดอนุมัติ ระบบต้องส่งเอกสารต่อให้อาจารย์ที่ปรึกษา (เชื่อม UC-05)
  เปลี่ยนสถานะเอกสารเป็น "ส่งต่ออาจารย์" และแจ้งกรรมการสโมสรว่าอนุมัติแล้ว        <- UC-03 Main Flow ขั้น 5 / Postcondition
- FR-VDC-06 เมื่อเจ้าหน้าที่พบว่าเอกสารไม่ครบ และกดตีกลับพร้อมระบุเหตุผล ระบบต้องเปลี่ยนสถานะ
  เอกสารเป็น "ตีกลับให้แก้ไข" และแจ้งกรรมการสโมสรพร้อมเหตุผลที่ระบุ (ย้อนกลับ UC-01)  <- UC-03 Alternative Flow 4a
- FR-VDC-07 ระบบต้องยึดเกณฑ์ Checklist กลางฉบับล่าสุดเป็นหลักเสมอสำหรับเจ้าหน้าที่ทุกคน
  เพื่อไม่ให้แต่ละคนตรวจสอบด้วยเกณฑ์ที่แตกต่างกัน                            <- UC-03 Exception Flow 5a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงคิวและรายละเอียดเอกสารโครงการ ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-VDC-01 (FR-VDC-05)
      Given เอกสารครบตาม Checklist กลาง
      When  เจ้าหน้าที่กดอนุมัติ
      Then  ระบบส่งต่อให้อาจารย์ที่ปรึกษา และแจ้งกรรมการสโมสรว่าอนุมัติแล้ว
- [ ] AC-VDC-02 (FR-VDC-06)
      Given เอกสารไม่ครบตาม Checklist
      When  เจ้าหน้าที่กดตีกลับพร้อมเหตุผล
      Then  ระบบแจ้งกรรมการสโมสรพร้อมเหตุผลที่ระบุ
- [ ] AC-VDC-03 (FR-VDC-01)
      Given มีเอกสารโครงการหลายฉบับรอตรวจสอบ
      When  เจ้าหน้าที่เปิดคิวเอกสาร
      Then  ระบบแสดงลิสต์เรียงตามวันที่ส่งเข้าก่อน-หลัง
- [ ] AC-VDC-04 (FR-VDC-03)
      Given เจ้าหน้าที่เปิดดูรายละเอียดโครงการหนึ่ง
      When  ระบบตรวจสอบเอกสารกับเกณฑ์
      Then  ระบบแสดง Checklist ระบุรายการที่ครบ/ไม่ครบตามเกณฑ์กลางฉบับล่าสุด
- [ ] AC-VDC-05 (FR-VDC-07)
      Given เจ้าหน้าที่สองคนเปิดตรวจเอกสารในช่วงที่เกณฑ์กลางเพิ่งถูกปรับปรุง
      When  ทั้งสองคนเปิด Checklist ของเอกสาร
      Then  ทั้งสองคนเห็นเกณฑ์ชุดเดียวกัน (เกณฑ์กลางฉบับล่าสุด) ไม่มีความแตกต่างกัน
- [ ] AC-VDC-06 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงคิวหรือรายละเอียดเอกสารโครงการ
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 "เกณฑ์กลาง/เกณฑ์กลางฉบับล่าสุด" หมายถึงชุดเกณฑ์ Checklist เดียวที่ดูแลอยู่ที่ส่วนกลาง
  (ยังไม่ระบุ owner หรือ use case ที่ใช้ปรับปรุงเกณฑ์)
- ASM-02 ข้อความ Exception Flow 5a ในภาพต้นฉบับอ่านไม่ชัดเจน ตีความว่าเป็นกรณีเจ้าหน้าที่แต่ละคน
  อาจใช้เกณฑ์คนละเวอร์ชัน แล้วระบบบังคับใช้เกณฑ์กลางฉบับล่าสุดเสมอ (ดู Q-02)
- Q-01 เกณฑ์ Checklist กลาง ถูกกำหนด/ปรับปรุงโดยใคร และผ่าน use case ใด (ยังไม่ระบุในตาราง
  เช่นเดียวกับ UC-01, UC-02 ก่อนหน้านี้)
- Q-02 ข้อความ Exception Flow 5a ในภาพต้นฉบับไม่สมบูรณ์/อ่านไม่ชัด -> ขอภาพที่ชัดกว่านี้เพื่อยืนยันเนื้อหาที่ถูกต้อง
- Q-03 การแจ้งกรรมการสโมสรเมื่ออนุมัติ (AC-VDC-01) เป็นการแจ้งแบบ synchronous หรือ asynchronous
  (เทียบกับรูปแบบ IF-NOT-01 ในสเปกอื่น) ยังไม่ระบุในตาราง
- Q-04 การตีกลับ (Alternative Flow 4a) ส่งเอกสารกลับไปที่ UC-01 ทั้งฉบับ หรือกรรมการแก้ไขเฉพาะจุด
  ที่ระบุเหตุผลได้เลยโดยไม่ต้องกรอกใหม่ทั้งหมด?
- Q-05 หากเจ้าหน้าที่หลายคนเปิดตรวจเอกสารฉบับเดียวกันพร้อมกัน (มาจากคิวเดียวกัน) ระบบป้องกัน
  การอนุมัติ/ตีกลับซ้ำซ้อนกันอย่างไร?
