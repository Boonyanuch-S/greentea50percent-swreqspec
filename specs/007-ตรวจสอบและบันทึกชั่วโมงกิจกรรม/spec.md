# Feature: ตรวจสอบและบันทึกชั่วโมงกิจกรรม (Verify & Record Activity Hours)
Spec ID: SPEC-HRS-007 | Source: UC-07 (Use Case Table) | Use case: UC-07
Owner: ทีม A | Status: Draft v2 | Updated: 2569-09-20

## Goal
เจ้าหน้าที่กองการนักศึกษาตรวจสอบใบสรุปชั่วโมงกิจกรรม (Excel) ที่กรรมการสโมสรส่งเข้ามา
เทียบกับเกณฑ์ประเภทชั่วโมงที่กำหนดของปีการศึกษานั้น แล้วบันทึกชั่วโมงเข้าระบบ REG
เพื่อให้ชั่วโมงกิจกรรมของนักศึกษาขึ้น REG ได้เร็วและถูกต้อง โดยไม่ต้องแก้ไขเอกสารซ้ำภายหลัง

## Scope
### In scope
- แสดงคิวเอกสาร (ใบสรุปชั่วโมงกิจกรรม) ที่รอตรวจสอบ เรียงตามวันที่ส่งก่อน-หลัง
- แสดงรายชื่อผู้เข้าร่วมกิจกรรมพร้อมประเภทชั่วโมงที่แจ้งไว้ จากไฟล์ Excel ที่เจ้าหน้าที่เลือก
- ตรวจสอบประเภทชั่วโมงในเอกสารเทียบกับเกณฑ์ที่กำหนดของปีการศึกษานั้น ก่อนยืนยันอนุมัติ
- บันทึกชั่วโมงเข้าระบบ REG เมื่อยืนยันอนุมัติ และเปลี่ยนสถานะเอกสารเป็น "บันทึกชั่วโมงสำเร็จ"
- เรียก UC-10 เพื่อแจ้งยืนยันกลับไปยังสโมสรเมื่อบันทึกสำเร็จ
### Out of scope
- การส่งไฟล์ Excel ชั่วโมงกิจกรรมโดยกรรมการสโมสร (UC-02) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition/trigger)
- เนื้อหาและกลไกการแสดงสรุปข้อมูลรายบุคคลโดยละเอียด (UC-04) - ฟีเจอร์นี้เรียกใช้เป็น alternative flow เท่านั้น
- เนื้อหา/ช่องทางการแจ้งเตือนกลับสโมสร (UC-10)
- การขอยืนยันชั่วโมงย้อนหลัง/กรณีล่าช้า (UC-11)
- ยืนยันตัวตนเจ้าหน้าที่ (Login) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition, อ้างอิง NFR ข้อ 21)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตนเจ้าหน้าที่ (Login) ก่อนเข้าถึงคิวตรวจสอบและข้อมูลชั่วโมงกิจกรรมของนักศึกษา
- DOM-PDPA-01 การเข้าถึงข้อมูลนักศึกษาต้องบันทึก log ทุกครั้ง (ผู้เข้าถึง, เวลา, รายการที่เข้าถึง)
  อ้างอิง NFR ข้อ 20 (DOMAIN/PDPA) — หมายเหตุ: ต้นฉบับระบุว่าข้อนี้ "ไม่มีในรายการ NFR 20 ข้อเดิม ต้องตรวจเพิ่ม" (ดู Q-02)
- IF-REG-01 ระบบต้องส่งข้อมูลชั่วโมงไปบันทึกที่ระบบ REG (ภายนอก) และต้องรองรับกรณี REG ไม่ตอบสนองระหว่างส่งข้อมูล
- IF-XLS-01 ระบบต้องอ่านไฟล์ Excel ชั่วโมงกิจกรรมที่ส่งมาจาก UC-02 (รายชื่อผู้เข้าร่วม + ประเภทชั่วโมงที่แจ้งไว้)

## Requirements
- FR-HRS-01 ระบบต้องแสดงคิวเอกสาร (ใบสรุปชั่วโมงกิจกรรม) ที่รอตรวจสอบ เรียงตามวันที่ส่งก่อน-หลัง
                                                                        <- UC-07 Main Flow ขั้น 1
- FR-HRS-02 เมื่อเจ้าหน้าที่เลือกไฟล์ Excel ชั่วโมงกิจกรรมของกิจกรรมหนึ่ง ระบบต้องแสดงรายชื่อผู้เข้าร่วม
  พร้อมประเภทชั่วโมงที่แจ้งไว้ในไฟล์ครบทุกรายการ                          <- UC-07 Main Flow ขั้น 2-3
- FR-HRS-03 ระบบต้องให้เจ้าหน้าที่ตรวจสอบประเภทชั่วโมงในเอกสารเทียบกับเกณฑ์ที่กำหนดของปีการศึกษานั้น
  ก่อนยืนยันอนุมัติ                                                     <- UC-07 Main Flow ขั้น 4
- FR-HRS-04 เมื่อเจ้าหน้าที่กดยืนยันอนุมัติ และประเภทชั่วโมงทุกรายการตรงตามเกณฑ์ ระบบต้องส่งข้อมูล
  ไปบันทึกที่ระบบ REG และเปลี่ยนสถานะเอกสารเป็น "บันทึกชั่วโมงสำเร็จ"        <- UC-07 Main Flow ขั้น 5-6 / Postcondition
- FR-HRS-05 เมื่อบันทึกชั่วโมงสำเร็จ ระบบต้องเรียก UC-10 เพื่อแจ้งยืนยันกลับไปยังสโมสร
                                                                        <- UC-07 Main Flow ขั้น 7 / Postcondition
- FR-HRS-06 หากใบสรุปชั่วโมงมีรายการประเภทชั่วโมงอย่างน้อย 1 รายการไม่ตรงกับเกณฑ์ที่กำหนด
  ระบบต้องปฏิเสธการยืนยันอนุมัติ แจ้งเตือนเจ้าหน้าที่ และคืนเอกสารทั้งฉบับกลับไปที่ UC-02
  โดยต้องแสดงหรือทำเครื่องหมายเฉพาะรายการที่ไม่ตรงเกณฑ์เป็นจุดที่ต้องแก้ไข และไม่บันทึกชั่วโมงรายการใดเลยจนกว่าจะแก้ไข
                                                                        <- UC-07 Exception Flow 4a
- FR-HRS-07 หากระบบ REG ไม่ตอบสนองระหว่างส่งข้อมูลไปบันทึก ระบบต้องแจ้ง "ส่งข้อมูลไม่สำเร็จ"
  ให้เจ้าหน้าที่ลองส่งซ้ำได้ และแจ้งเตือนเจ้าหน้าที่หากส่งซ้ำไม่สำเร็จ           <- UC-07 Exception Flow 6a
- FR-HRS-08 ระบบต้องให้เจ้าหน้าที่ดูสรุปข้อมูลรายบุคคลของผู้เข้าร่วม (เรียกใช้ UC-04) ก่อนตัดสินใจ
  ได้ในระหว่างขั้นตรวจสอบเกณฑ์ แล้วกลับไปที่ขั้นตรวจสอบเกณฑ์ต่อ (ขั้นที่ 4)      <- UC-07 Alternative Flow 3a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงคิวตรวจสอบและข้อมูลชั่วโมงกิจกรรม ต้องผ่านการยืนยันตัวตน (Login) ก่อน
- NFR-SEC-02 (อ้างอิง NFR ข้อ 20 - DOMAIN/PDPA) การเข้าถึงข้อมูลนักศึกษาทุกครั้งต้องมี log ที่ระบุผู้เข้าถึง
  เวลา และรายการที่เข้าถึง (ดู Q-02 เรื่องสถานะของข้อนี้ในเอกสาร NFR หลัก)
- NFR-PERF-01 (อ้างอิง NFR ข้อ 6) การส่งข้อมูลไปบันทึกที่ระบบ REG หลังยืนยันอนุมัติ ต้องสำเร็จภายในเวลาที่กำหนด
  (ต้นฉบับยังไม่ระบุตัวเลขเวลาที่ชัดเจน — ดู Q-03)

## Acceptance Criteria
- [ ] AC-HRS-01 (FR-HRS-04)
      Given ใบสรุปชั่วโมงที่ส่งเข้ามา มีประเภทงานตรงกับเกณฑ์ที่กำหนดครบทุกรายชื่อ
      When  เจ้าหน้าที่ยืนยันอนุมัติ
      Then  ระบบบันทึกชั่วโมงเข้าระบบ REG สำเร็จ และเปลี่ยนสถานะเอกสารเป็น "บันทึกชั่วโมงสำเร็จ"
- [ ] AC-HRS-02 (FR-HRS-06)
      Given ใบชั่วโมงมีประเภทงานอย่างน้อย 1 รายการที่ไม่ตรงกับเกณฑ์
      When  เจ้าหน้าที่พยายามยืนยันอนุมัติ
  Then  ระบบปฏิเสธการบันทึก แจ้งเตือนเจ้าหน้าที่ คืนเอกสารทั้งฉบับไปยัง UC-02
    และแสดงหรือทำเครื่องหมายเฉพาะรายการที่ไม่ตรงเกณฑ์เป็นจุดที่ต้องแก้ไข
    โดยไม่บันทึกชั่วโมงจนกว่าจะแก้ไขรายการนั้น
- [ ] AC-HRS-03 (FR-HRS-01)
      Given มีเอกสารใบสรุปชั่วโมงกิจกรรมหลายฉบับรอตรวจสอบ
      When  เจ้าหน้าที่เปิดคิวเอกสารรอตรวจสอบ
      Then  ระบบแสดงลิสต์เอกสารเรียงตามวันที่ส่งก่อน-หลัง
- [ ] AC-HRS-04 (FR-HRS-02)
      Given เจ้าหน้าที่เลือกไฟล์ Excel ชั่วโมงกิจกรรมของกิจกรรมหนึ่ง
      When  ระบบเปิดไฟล์นั้น
      Then  ระบบแสดงรายชื่อผู้เข้าร่วมพร้อมประเภทชั่วโมงที่แจ้งไว้ครบทุกรายการ
- [ ] AC-HRS-05 (FR-HRS-05)
      Given บันทึกชั่วโมงเข้าระบบ REG สำเร็จ
      When  สถานะเอกสารเปลี่ยนเป็น "บันทึกชั่วโมงสำเร็จ"
      Then  ระบบเรียก UC-10 เพื่อส่งแจ้งยืนยันกลับไปยังสโมสร
- [ ] AC-HRS-06 (FR-HRS-07)
      Given เจ้าหน้าที่ยืนยันอนุมัติและประเภทชั่วโมงตรงตามเกณฑ์ครบ แต่ระบบ REG ไม่ตอบสนองระหว่างส่งข้อมูล
      When  ระบบพยายามบันทึกข้อมูล
      Then  ระบบแจ้ง "ส่งข้อมูลไม่สำเร็จ" ให้เจ้าหน้าที่ลองส่งซ้ำได้ และแจ้งเตือนเจ้าหน้าที่หากส่งซ้ำไม่สำเร็จ
- [ ] AC-HRS-07 (FR-HRS-08)
      Given เจ้าหน้าที่ต้องการดูสรุปข้อมูลรายบุคคลของผู้เข้าร่วมก่อนตัดสินใจ
      When  เจ้าหน้าที่เลือกดูสรุปข้อมูล (เรียก UC-04)
      Then  ระบบแสดงสรุปข้อมูลรายบุคคลที่เลือก แล้วกลับไปยังขั้นตรวจสอบเกณฑ์ (ขั้นที่ 4)
- [ ] AC-HRS-08 (NFR-SEC-01)
      Given เจ้าหน้าที่ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงคิวตรวจสอบชั่วโมงกิจกรรม
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ
- [ ] AC-HRS-09 (NFR-SEC-02 / DOM-PDPA-01)
      Given มีการเปิดดูข้อมูลรายชื่อหรือชั่วโมงของนักศึกษา
      When  การเข้าถึงเสร็จสิ้น
      Then  มี log ที่ระบุผู้เข้าถึง เวลา และรายการที่เข้าถึง

## Assumptions & Open Questions
- ASM-01 "ปีการศึกษานั้น" หมายถึงปีการศึกษาที่ตรงกับวันที่ส่งเอกสาร/วันที่ตรวจสอบ
- ASM-02 "เกณฑ์ที่กำหนด" อ้างอิงจากตารางเกณฑ์ประเภทชั่วโมงที่มีอยู่แล้วในระบบ ที่มา/เจ้าของเกณฑ์นี้ไม่ได้ระบุใน UC-07 (ดู Q-05)
- ASM-03 เมื่อไม่ตรงเกณฑ์ ให้คืนเอกสารทั้งฉบับไปยัง UC-02 พร้อมแสดงหรือทำเครื่องหมายเฉพาะรายการที่ผิดเพื่อให้แก้ไข
- Q-01 ข้อความ Exception Flow ขั้น 6b ในตารางต้นฉบับ ("หากเชื่อมต่อล่าช้าจากการกำหนด → ระบบเรียก UC-11
  ขอยืนยันชั่วโมงหลัง...") อ่านไม่ชัดเจนจากภาพที่แนบมา ยังไม่ได้แปลงเป็น FR ในสเปกนี้
  -> ขอภาพ/เอกสารต้นฉบับที่ชัดเจนกว่านี้ หรือสอบถามผู้เขียน use case เพื่อยืนยันเงื่อนไขและพฤติกรรม
- Q-02 ต้นฉบับระบุว่า NFR "การเข้าถึงข้อมูลนักศึกษาต้องมี log ทุกครั้ง" ไม่มีอยู่ในรายการ NFR 20 ข้อเดิม
  ต้องยืนยันว่าเป็นข้อกำหนดใหม่ที่ต้องเพิ่ม หรือมีอยู่แล้วแต่ระบุไม่ครบ -> ถามทีมที่ดูแลเอกสาร NFR หลัก
- Q-03 NFR-PERF (อ้างอิง ข้อ 6) ระบุ "บันทึก REG สำเร็จภายในเวลาที่กำหนด" แต่ไม่มีตัวเลขเวลาที่ชัดเจนในต้นฉบับ
  -> ต้องระบุค่าตัวเลข (เช่น กี่วินาที/นาที) เพื่อให้ AC-HRS ที่เกี่ยวข้องทดสอบได้จริง
- Q-05 เกณฑ์รายประเภทชั่วโมง (จิตอาสา/กศ./ฯลฯ) ถูกดูแล/ตั้งค่าโดย use case ใด (อาจเป็น UC อื่นที่ยังไม่ระบุในตาราง)
  -> ต้องยืนยัน owner ของเกณฑ์นี้ก่อนเขียน integration ต่อ
- Q-06 Goal ระบุว่าไม่ต้องแก้ไขเอกสารซ้ำภายหลัง แต่ FR-HRS-06 ระบุให้คืนเอกสารทั้งฉบับเพื่อแก้ไข
  ต้องยืนยันว่าควรปรับ Goal ให้สอดคล้องกับการคืนเอกสารเมื่อพบรายการผิดหรือไม่
  -> ถามทีมเจ้าของกระบวนการ/ทีมผู้เขียน spec
