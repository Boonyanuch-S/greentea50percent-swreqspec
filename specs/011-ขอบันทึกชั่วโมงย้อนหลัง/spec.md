## Goal
กรรมการสโมสรนักศึกษายื่นขอบันทึกชั่วโมงกิจกรรมย้อนหลังเมื่อพลาดกำหนดเวลาปกติ (UC-02)
โดยประสานงานกับเจ้าหน้าที่คณะวิทยาศาสตร์เพื่อทำเล่มสรุปโครงการใหม่ (เรียก UC-04) ก่อนส่งไฟล์ Excel
ชั่วโมงกิจกรรมเข้าสู่กระบวนการตรวจสอบของกองกิจอีกครั้ง (เรียก UC-07) เพื่อให้กระบวนการยื่นย้อนหลัง
ไม่ยุ่งยากซ้ำซ้อน และมีหลักฐาน/เหตุผลที่ชัดเจนสำหรับทุกฝ่าย

## Scope
### In scope
- แสดงรายการกิจกรรมของกรรมการที่เลยกำหนดเวลาปกติสำหรับยื่นชั่วโมงกิจกรรม
- ให้กรรมการกรอกเหตุผลความล่าช้าและแนบเอกสารประกอบ
- ส่งคำขอไปยังเจ้าหน้าที่คณะวิทยาศาสตร์เพื่อขอทำเล่มสรุปโครงการใหม่ (เชื่อม UC-04)
- ให้กรรมการอัปโหลดไฟล์ Excel ชั่วโมงกิจกรรมอีกครั้ง พร้อมอ้างอิงคำขอย้อนหลัง
- ส่งเรื่องเข้าคิวตรวจสอบของเจ้าหน้าที่กองกิจ พร้อม flag "ยื่นย้อนหลัง" (เชื่อม UC-07)
- ปฏิเสธคำขอเล่มสรุปใหม่เมื่อเอกสารต้นทางไม่ครบ และให้กรรมการแก้ไข
- แสดงสถานะให้ติดตามระหว่างรอเล่มสรุปจากคณะ
- ไม่ใช้ระยะเวลาสูงสุดเป็นเงื่อนไขปฏิเสธคำขอยื่นย้อนหลัง
- บันทึก log แยกอย่างชัดเจนว่าเรื่องใดเป็นการยื่นย้อนหลัง เพื่อความโปร่งใส
### Out of scope
- การส่งข้อมูลชั่วโมงตามกำหนดเวลาปกติ (UC-02) - เป็นบริบท/ทริกเกอร์ของฟีเจอร์นี้เท่านั้น
- การจัดทำเล่มสรุปโครงการใหม่โดยเจ้าหน้าที่คณะเอง (รายละเอียดอยู่ใน UC-04)
- การตรวจสอบไฟล์ชั่วโมงกิจกรรมโดยเจ้าหน้าที่กองกิจ (รายละเอียดอยู่ใน UC-07)
- เข้าสู่ระบบ / ยืนยันตัวตน (UC-09) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- การกำหนดระยะเวลาสูงสุดที่มหาวิทยาลัยอนุญาตให้ยื่นย้อนหลัง เพราะฟีเจอร์นี้ไม่ใช้ระยะเวลาดังกล่าวเป็นเงื่อนไขปฏิเสธ

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- DOM-PDPA-03 ระบบต้องบันทึก log การเข้าถึงข้อมูลตาม NFR ข้อ 20 (DOMAIN/PDPA) — หมายเหตุต้นฉบับระบุว่า
  รายละเอียดนี้ "ยังไม่มีในรายการ NFR 20 ข้อเดิม ควรเพิ่ม" (ประเด็นเดียวกับที่เคยพบใน UC-07 - ดู Q-04)
- DOM-AUDIT-02 ระบบต้องบันทึก log แยกอย่างชัดเจนว่าเรื่องใดเป็นการยื่นย้อนหลัง เพื่อความโปร่งใสจากกรณีปกติ
- IF-UC04-01 ระบบต้องส่งคำขอไปยัง UC-04 เพื่อให้เจ้าหน้าที่คณะจัดทำเล่มสรุปโครงการใหม่
- IF-UC07-02 เมื่อกรรมการอัปโหลดไฟล์ Excel ชั่วโมงอีกครั้ง ระบบต้องส่งเข้าคิวของ UC-07 พร้อม flag "ยื่นย้อนหลัง"
- IF-DEADLINE-01 ระบบต้องไม่ใช้ระยะเวลาสูงสุดที่มหาวิทยาลัยกำหนดเป็นเงื่อนไขปฏิเสธ
  คำขอยื่นย้อนหลัง เนื่องจากฟีเจอร์นี้ไม่กำหนดระยะเวลาสูงสุด

## Requirements
- FR-LATE-01 ระบบต้องแสดงรายการกิจกรรมของกรรมการสโมสรที่เลยกำหนดเวลาปกติสำหรับยื่นชั่วโมงกิจกรรม
  เมื่อเปิดหน้าคำขอบันทึกชั่วโมงย้อนหลัง                                    <- UC-11 Main Flow ขั้น 1-2
- FR-LATE-02 ระบบต้องให้กรรมการสโมสรกรอกเหตุผลความล่าช้าและแนบเอกสารประกอบ สำหรับกิจกรรมที่เลือก
                                                                        <- UC-11 Main Flow ขั้น 3
- FR-LATE-03 เมื่อกรรมการส่งคำขอ ระบบต้องส่งคำขอไปยังเจ้าหน้าที่คณะวิทยาศาสตร์เพื่อขอทำเล่มสรุปโครงการใหม่
  (เรียก UC-04) และเปลี่ยนสถานะเป็น "ยื่นย้อนหลัง - รอตรวจสอบ"                <- UC-11 Main Flow ขั้น 4 / Postcondition
- FR-LATE-04 ระบบต้องให้กรรมการอัปโหลดไฟล์ Excel ชั่วโมงกิจกรรมอีกครั้ง พร้อมอ้างอิงคำขอยื่นย้อนหลังนี้
  หลังเล่มสรุปโครงการใหม่เสร็จ                                             <- UC-11 Main Flow ขั้น 6
- FR-LATE-05 เมื่ออัปโหลดไฟล์แล้ว ระบบต้องส่งเรื่องเข้าคิวตรวจสอบของเจ้าหน้าที่กองกิจ (เรียก UC-07)
  พร้อม flag "ยื่นย้อนหลัง"                                                <- UC-11 Main Flow ขั้น 7
- FR-LATE-06 หากเจ้าหน้าที่คณะวิทยาศาสตร์ปฏิเสธคำขอเล่มสรุปใหม่เพราะเอกสารต้นทางไม่ครบ ระบบต้องแจ้ง
  กรรมการสโมสรให้แก้ไขเอกสาร แล้วพากลับไปยังขั้นกรอกเหตุผล/แนบเอกสาร (ขั้นที่ 3)   <- UC-11 Alternative Flow 4a
- FR-LATE-07 หากสำนักงานคณะยังทำเล่มสรุปไม่เสร็จ ระบบต้องแสดงสถานะ "รอเล่มสรุปจากคณะ" ให้กรรมการ
  สโมสรติดตามได้เอง โดยไม่ต้องติดต่อสอบถามด้วยตนเอง                          <- UC-11 Exception Flow 5a
- FR-LATE-08 ระบบต้องไม่ปฏิเสธคำขอยื่นย้อนหลังด้วยเหตุผลว่าคำขอเกินระยะเวลาสูงสุด
  เนื่องจากฟีเจอร์นี้ไม่กำหนดระยะเวลาสูงสุด                                      <- UC-11 Exception Flow 7a
- FR-LATE-09 ระบบต้องบันทึก log แยกอย่างชัดเจนว่าเรื่องใดเป็นการยื่นย้อนหลัง เพื่อความโปร่งใสจากกรณีปกติ
                                                                        <- UC-11 NFR ที่เกี่ยวข้อง (หมายเหตุท้ายตาราง)

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์ขอบันทึกชั่วโมงย้อนหลัง ต้องผ่านการยืนยันตัวตน (Login) ก่อน
- NFR-SEC-03 (อ้างอิง NFR ข้อ 20 - DOMAIN/PDPA) ต้องมี log การเข้าถึงข้อมูล (สถานะของข้อนี้ในเอกสาร
  NFR หลักยังไม่ยืนยัน - ดู Q-04)

## Acceptance Criteria
- [ ] AC-LATE-01 (FR-LATE-03)
      Given กิจกรรมหนึ่งเลยกำหนดเวลาขึ้นชั่วโมงไปแล้ว
      When  กรรมการสโมสรยื่นคำขอย้อนหลังพร้อมเหตุผล
      Then  ระบบต้องส่งคำขอไปยังเจ้าหน้าที่คณะวิทย์เพื่อทำเล่มสรุปใหม่ และเปลี่ยนสถานะเป็น
            "ยื่นย้อนหลัง - รอตรวจสอบ"
- [ ] AC-LATE-02 (FR-LATE-08)
  Given คำขอยื่นย้อนหลังมีอายุหลังวันที่กิจกรรมสิ้นสุด
  When  เจ้าหน้าที่กองกิจตรวจสอบคำขอ
  Then  ระบบต้องไม่ปฏิเสธคำขอด้วยเหตุผลเรื่องระยะเวลาสูงสุด
- [ ] AC-LATE-03 (FR-LATE-01)
      Given กรรมการสโมสรมีกิจกรรมที่เลยกำหนดเวลาปกติหลายรายการ
      When  เปิดหน้าคำขอบันทึกชั่วโมงย้อนหลัง
      Then  ระบบแสดงรายการกิจกรรมที่เลยกำหนดเวลาปกติทั้งหมดของกรรมการนั้น
- [ ] AC-LATE-04 (FR-LATE-06)
      Given เจ้าหน้าที่คณะวิทยาศาสตร์ปฏิเสธคำขอเล่มสรุปใหม่เพราะเอกสารต้นทางไม่ครบ
      When  ระบบได้รับผลปฏิเสธ
      Then  ระบบแจ้งกรรมการสโมสรให้แก้ไขเอกสาร และพากลับไปยังขั้นกรอกเหตุผล/แนบเอกสาร
- [ ] AC-LATE-05 (FR-LATE-07)
      Given สำนักงานคณะยังทำเล่มสรุปโครงการใหม่ไม่เสร็จ
      When  กรรมการสโมสรเปิดดูสถานะคำขอ
      Then  ระบบแสดงสถานะ "รอเล่มสรุปจากคณะ" ให้ติดตามได้
- [ ] AC-LATE-06 (FR-LATE-09)
      Given มีคำขอทั้งแบบปกติและแบบยื่นย้อนหลังปะปนกันในระบบ
      When  เจ้าหน้าที่เปิดดู log
      Then  log ระบุชัดเจนว่ารายการใดเป็นการยื่นย้อนหลัง แยกจากกรณีปกติ
- [ ] AC-LATE-07 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์ขอบันทึกชั่วโมงย้อนหลัง
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 การตรวจสอบคำขอยื่นย้อนหลังไม่ขึ้นกับค่าระยะเวลาสูงสุดที่กรรมการหรือเจ้าหน้าที่กำหนดเองต่อคำขอ
- ASM-02 ฟีเจอร์นี้ไม่กำหนดและไม่ใช้ระยะเวลาสูงสุดที่มหาวิทยาลัยกำหนดเป็นเงื่อนไขปฏิเสธ
- Q-02 หากเจ้าหน้าที่กองกิจปฏิเสธคำขอ (7a) กรรมการสโมสรมีทางเลือกอื่นอีกหรือไม่ (เช่น อุทธรณ์)
  หรือจบกระบวนการทันที?
- Q-03 การจัดทำเล่มสรุปโครงการใหม่ (ขั้นที่ 5, เรียก UC-04) ใช้ฟอร์ม/ฟีเจอร์เดียวกับการสร้างโครงการใหม่ปกติ
  หรือมีเวอร์ชันเฉพาะสำหรับกรณีย้อนหลัง (เช่น ต้องอ้างอิงโครงการเดิม)?
- Q-04 NFR ข้อ 20 (DOMAIN/PDPA log) ระบุว่า "ยังไม่มีใน 20 ข้อเดิม ควรเพิ่ม" เช่นเดียวกับที่เคยพบใน UC-07
  -> ควรยืนยันกับทีมที่ดูแลเอกสาร NFR หลักว่าจะเพิ่มข้อนี้อย่างเป็นทางการหรือไม่ (ประเด็นซ้ำข้ามหลายสเปก)
- Q-05 กรรมการสโมสรยื่นคำขอย้อนหลังได้กี่ครั้งต่อกิจกรรมหนึ่ง (เช่น ถ้าถูกปฏิเสธในขั้น 7a แล้ว ยื่นใหม่ได้อีกหรือไม่)?
- Q-06 ไฟล์ Excel ที่อัปโหลดต้องมีรูปแบบ ขนาด และข้อมูลอ้างอิงใดบ้างก่อนส่งเข้า UC-07?
- Q-07 การตรวจสอบของเจ้าหน้าที่กองกิจใน AC-LATE-02 หมายถึงการตรวจเงื่อนไขของคำขอเท่านั้น หรือรวมการตรวจไฟล์ตาม UC-07 ด้วย?
- Q-08 Log ของคำขอย้อนหลังต้องบันทึกเหตุการณ์และข้อมูลใดบ้าง รวมถึงใครมีสิทธิ์ดูและเก็บไว้นานเท่าใด?
