# แผนทางเทคนิค: ขอบันทึกชั่วโมงย้อนหลัง

## 1. สรุปแนวทาง
ฟีเจอร์นี้ให้กรรมการสโมสรค้นหากิจกรรมที่เลยกำหนดปกติและสร้างคำขอยื่นชั่วโมงย้อนหลัง (`FR-LATE-01`, `FR-LATE-02`).
ระบบจะเก็บเหตุผล เอกสารประกอบ และสถานะคำขอ พร้อมส่งคำขอไปยัง UC-04 (`FR-LATE-03`, `IF-UC04-01`).
เมื่อเล่มสรุปโครงการใหม่เสร็จ กรรมการจะอัปโหลดไฟล์ Excel ที่อ้างอิงคำขอเดิม (`FR-LATE-04`).
ระบบจะส่งไฟล์เข้าคิว UC-07 พร้อม flag ยื่นย้อนหลัง (`FR-LATE-05`, `IF-UC07-02`) โดยไม่ตรวจรายละเอียดไฟล์แทน UC-07.
ระบบจะแสดงผลการปฏิเสธ การรอเล่มสรุป และบันทึก audit log แยกจากกรณีปกติ (`FR-LATE-06` ถึง `FR-LATE-09`).

| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้จัดการคำขอ สถานะ การอ้างอิง UC-04/UC-07 และ audit log ตาม `FR-LATE-03` ถึง `FR-LATE-09` |
| ฐานข้อมูลเชิงสัมพันธ์ | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บคำขอ สถานะ เอกสารอ้างอิง และความสัมพันธ์กับกิจกรรม; ชนิดฐานข้อมูลจริงยังไม่กำหนดใน spec |
| Object storage สำหรับเอกสารและไฟล์ Excel | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้เก็บเอกสารประกอบและไฟล์ Excel ตาม `FR-LATE-02`, `FR-LATE-04`; ชนิดบริการและนโยบาย retention ยังรอ `Q-06`, `Q-08` |
| Internal API/adapter สำหรับ UC-04 และ UC-07 | `IF-UC04-01`, `IF-UC07-02` | ต้องแยก contract ของแต่ละ UC และยังไม่กำหนดรายละเอียด error/retry จนกว่าจะตอบ `Q-03`, `Q-04`, `Q-07` |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| `LateSubmissionRequest` | รหัสคำขอ, รหัสกรรมการ, รายการกิจกรรมที่เลือก, เหตุผลความล่าช้า, สถานะ, flag ยื่นย้อนหลัง, รหัสอ้างอิง UC-04/UC-07 | `FR-LATE-01` ถึง `FR-LATE-08`, `IF-UC04-01`, `IF-UC07-02` |
| `Activity` | รหัสกิจกรรม, ข้อมูลกิจกรรมที่ใช้แสดงรายการกิจกรรมเลยกำหนด, ความสัมพันธ์กับกรรมการ | `FR-LATE-01`, `AC-LATE-03` |
| `SupportingDocument` | รหัสเอกสาร, รหัสคำขอ, ชนิดเอกสาร, ตำแหน่งไฟล์, เวอร์ชันเอกสาร, สถานะการตรวจรับ | `FR-LATE-02`, `FR-LATE-06`, `AC-LATE-04` |
| `SummaryBookRequest` | รหัสคำขอ, รหัสอ้างอิงคำขอยื่นย้อนหลัง, สถานะการทำเล่ม, ผลตอบกลับจาก UC-04 | `FR-LATE-03`, `FR-LATE-06`, `FR-LATE-07`, `IF-UC04-01` |
| `HourExcelSubmission` | รหัสไฟล์, รหัสคำขอยื่นย้อนหลัง, ตำแหน่งไฟล์, สถานะการส่งต่อ, flag ยื่นย้อนหลัง, รหัสอ้างอิง UC-07 | `FR-LATE-04`, `FR-LATE-05`, `IF-UC07-02` |
| `AuditLog` | รหัสเหตุการณ์, รหัสคำขอ/ผู้ใช้งาน, เวลา, การกระทำ, สถานะก่อน/หลัง, ประเภทยื่นปกติหรือย้อนหลัง | `FR-LATE-09`, `DOM-PDPA-03`, `DOM-AUDIT-02`, `NFR-SEC-03` |

รายละเอียดจำนวนครั้งที่ยื่นซ้ำ รูปแบบเอกสาร รายละเอียดไฟล์ Excel สิทธิ์ดู log และระยะเวลาเก็บ log จะยังไม่ล็อกจนกว่าจะตอบ `Q-05`, `Q-06`, `Q-08`.

## 4. API / หน้าจอ

| รายการ | Input หลัก | Output หลัก | รองรับ |

| `POST /late-submissions/{request_id}/hour-file` | ไฟล์ Excel และรหัสคำขอยื่นย้อนหลัง | ผลการรับไฟล์และสถานะการส่งเข้า UC-07 | `FR-LATE-04`, `FR-LATE-05`, `IF-UC07-02`, `Q-06` |
| `POST /internal/uc04/summary-book-requests` | รหัสคำขอยื่นย้อนหลัง เหตุผล และเอกสารอ้างอิง | รหัสคำขอ UC-04 และผลรับคำขอ | `FR-LATE-03`, `IF-UC04-01`, `Q-03`, `Q-04` |
| `POST /internal/uc07/hour-submissions` | รหัสคำขอ ไฟล์ Excel และ flag `ยื่นย้อนหลัง` | รหัสรายการเข้าคิว UC-07 และผลรับเรื่อง | `FR-LATE-05`, `IF-UC07-02`, `Q-06`, `Q-07` |
| `GET /late-submissions/{request_id}/audit-logs` | รหัสคำขอและบริบทเจ้าหน้าที่ที่มีสิทธิ์ | log ที่แยกประเภทคำขอย้อนหลังจากกรณีปกติ | `FR-LATE-09`, `DOM-PDPA-03`, `DOM-AUDIT-02`, `NFR-SEC-03`, `AC-LATE-06`, `Q-08` |
| หน้ารายการกิจกรรม | ไม่มีเพิ่มเติมนอกจาก session ผู้ใช้ | รายการกิจกรรมที่เลือกได้ | `FR-LATE-01`, `AC-LATE-03` |

## 7. ลำดับงาน

1. ยืนยันสถานะ บทบาท และข้อมูลกิจกรรมที่กรรมการมีสิทธิ์เห็น (`CON-NFR-21`, `FR-LATE-01`, `AC-LATE-03`).
2. ออกแบบ `LateSubmissionRequest`, ความสัมพันธ์กิจกรรม เอกสารประกอบ และสถานะคำขอ (`FR-LATE-01` ถึง `FR-LATE-03`, `AC-LATE-01`, `Q-02`, `Q-03`).
3. สร้าง middleware/route guard และ audit event สำหรับการเข้าถึงฟีเจอร์ (`CON-NFR-21`, `DOM-PDPA-03`, `NFR-SEC-01`, `NFR-SEC-03`, `Q-04`, `Q-08`).
4. ออกแบบ adapter และ contract การส่งคำขอไป UC-04 รวมถึงผลลัพธ์รอ/ปฏิเสธ (`FR-LATE-03`, `FR-LATE-06`, `FR-LATE-07`, `IF-UC04-01`, `AC-LATE-04`, `AC-LATE-05`, `Q-03`, `Q-04`).
5. สร้างหน้าสร้างคำขอ การแนบเอกสาร และการวนกลับแก้ไข (`FR-LATE-02`, `FR-LATE-06`, `AC-LATE-01`, `AC-LATE-04`, `Q-05`).
6. สร้างการอัปโหลด Excel และ adapter ส่งเข้า UC-07 พร้อม flag ยื่นย้อนหลัง โดยไม่เพิ่มการตรวจที่อยู่นอก UC-07 (`FR-LATE-04`, `FR-LATE-05`, `IF-UC07-02`, `Q-06`, `Q-07`).
7. สร้างหน้าติดตามสถานะและ audit log ที่แยกกรณีปกติ/ย้อนหลัง (`FR-LATE-07`, `FR-LATE-09`, `DOM-AUDIT-02`, `AC-LATE-05`, `AC-LATE-06`, `Q-08`).
8. เขียน automated tests ตาม `AC-LATE-01` ถึง `AC-LATE-07` ด้วยข้อมูลจำลองและ stub ของ UC-04/UC-07.

## 8. สิ่งที่ยังไม่ทำ

- `Q-02` หากเจ้าหน้าที่กองกิจปฏิเสธคำขอ กรรมการสโมสรมีทางเลือกอื่น เช่น อุทธรณ์ หรือจบกระบวนการทันที? ส่วน workflow หลังปฏิเสธจะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-03` การจัดทำเล่มสรุปโครงการใหม่ใช้ฟอร์ม/ฟีเจอร์เดียวกับการสร้างโครงการใหม่ปกติ หรือมีเวอร์ชันเฉพาะสำหรับกรณีย้อนหลัง? ส่วน contract และข้อมูลที่ส่ง UC-04 จะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-04` NFR ข้อ 20 (DOMAIN/PDPA log) จะเพิ่มอย่างเป็นทางการในเอกสาร NFR หลักหรือไม่? ส่วนรายละเอียด log ที่อ้าง NFR ข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-05` กรรมการสโมสรยื่นคำขอย้อนหลังได้กี่ครั้งต่อกิจกรรมหนึ่ง และหลังถูกปฏิเสธยื่นใหม่ได้หรือไม่? ส่วนกติกาการยื่นซ้ำและการแก้ไขคำขอจะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-06` ไฟล์ Excel ต้องมีรูปแบบ ขนาด และข้อมูลอ้างอิงใดบ้างก่อนส่งเข้า UC-07? ส่วน validation และ contract ของไฟล์จะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-07` การตรวจสอบของเจ้าหน้าที่กองกิจใน `AC-LATE-02` รวมการตรวจไฟล์ตาม UC-07 ด้วยหรือไม่? ส่วนขอบเขตการตรวจและการส่งต่อจะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-08` Log ต้องบันทึกเหตุการณ์/ข้อมูลใด ใครมีสิทธิ์ดู และเก็บไว้นานเท่าใด? ส่วน schema สิทธิ์การดู และ retention ของ log จะยังไม่สร้างจนกว่าจะได้คำตอบ
