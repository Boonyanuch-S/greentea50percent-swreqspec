## Goal
กรรมการสโมสรนักศึกษาสร้างไฟล์ Excel สรุปชั่วโมงกิจกรรมของกิจกรรมที่จบแล้วโดยอัตโนมัติ
จากรายชื่อผู้เข้าร่วมและ Staff ตรวจสอบความครบถ้วนอีกครั้ง แล้วส่งเข้าสู่คิวตรวจสอบของ
เจ้าหน้าที่กองกิจ (UC-07) เพื่อให้ไฟล์อยู่ในรูปแบบมาตรฐานเดียวกันทุกครั้งและชั่วโมงขึ้น REG ได้เร็ว
โดยปกติเป็นการส่งข้อมูลชั่วโมงย้อนหลังหลังกิจกรรมสิ้นสุด ไม่ใช่การส่งตามกำหนดเวลาแบบคงที่

## Scope
### In scope
- เปิดหน้าส่งข้อมูลชั่วโมงได้เฉพาะกิจกรรมที่จบแล้ว
- ดึงรายชื่อผู้เข้าร่วมและ Staff ของกิจกรรม พร้อมใช้ประเภทชั่วโมงที่กำหนดไว้ระดับกิจกรรม (จิตอาสา/กศ./ฯลฯ)
- สร้างไฟล์ Excel สรุปชั่วโมงกิจกรรมตามเทมเพลตมาตรฐานของกองกิจ
- ให้กรรมการตรวจสอบความครบถ้วนของข้อมูลในไฟล์ก่อนยืนยันส่ง
- ส่งไฟล์เข้าสู่คิวของเจ้าหน้าที่กองกิจ (เชื่อม UC-07)
- แสดงสถานะและบล็อกการส่ง เมื่อเลขสรุปโครงการยังไม่พร้อม
- เสนอทางเลือกไปยัง UC-11 เมื่อมีการกำหนดเวลาส่งของกองกิจและเกินกำหนด
### Out of scope
- การขอ/ออกเลขสรุปโครงการ (UC-04) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- การตรวจสอบไฟล์ Excel โดยเจ้าหน้าที่กองกิจหลังเข้าคิว (UC-07)
- การขอผ่อนผันเวลาส่งช้า (UC-11) - ฟีเจอร์นี้เพียงเสนอทางเลือก/ลิงก์ไปเท่านั้น
- เข้าสู่ระบบ / ยืนยันตัวตน - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition, อ้างอิง NFR ข้อ 21)

## Constraints
- CON-NFR-21 ต้องยืนยันตัวตน (Login) ก่อนใช้งานฟีเจอร์นี้ทุกครั้ง
- IF-TPL-01 ระบบต้องสร้างไฟล์ Excel ตาม template ID/เวอร์ชันที่กำหนดไว้ใน config ของระบบ
  และให้กองกิจอัปโหลด/จัดการผ่านหน้าแอดมินโดยไม่ hardcode template ในโค้ด
- IF-PRJNUM-01 ระบบต้องตรวจสอบสถานะ "เลขสรุปโครงการ" จาก UC-04 ก่อนอนุญาตให้ส่งข้อมูลชั่วโมง
- IF-UC07-01 เมื่อส่งสำเร็จ ระบบต้องส่งไฟล์เข้าสู่คิวของ UC-07

## Requirements
- FR-SBH-01 ระบบต้องให้กรรมการเปิดหน้าส่งข้อมูลชั่วโมงได้เฉพาะกิจกรรมที่มีสถานะ "จบแล้ว"
                                                                        <- UC-02 Main Flow ขั้น 1
- FR-SBH-02 ระบบต้องดึงรายชื่อผู้เข้าร่วมและ Staff ของกิจกรรมนั้น พร้อมใช้ประเภทชั่วโมงที่กำหนดไว้
  ระดับกิจกรรม (จิตอาสา/กศ./ฯลฯ) โดยไม่กำหนดแยกตามรายบุคคลแยกกัน        <- UC-02 Main Flow ขั้น 2
- FR-SBH-03 ระบบต้องสร้างไฟล์ Excel สรุปชั่วโมงกิจกรรมตามเทมเพลตมาตรฐานของกองกิจ
                                                                        <- UC-02 Main Flow ขั้น 3
- FR-SBH-04 ระบบต้องให้กรรมการตรวจสอบความครบถ้วนของข้อมูลในไฟล์ ก่อนยืนยันส่ง
                                                                        <- UC-02 Main Flow ขั้น 4
- FR-SBH-05 เมื่อกรรมการกดยืนยันส่ง และเลขสรุปโครงการพร้อมแล้ว ระบบต้องส่งไฟล์ Excel
  เข้าสู่คิวของเจ้าหน้าที่กองกิจ (เชื่อม UC-07)                             <- UC-02 Main Flow ขั้น 5 / Postcondition
- FR-SBH-06 หากเลขสรุปโครงการยังไม่เสร็จ ระบบต้องแสดงสถานะ "ขอเลขสรุปจากกองกิจ"
  และไม่อนุญาตให้ดำเนินการส่งข้อมูลชั่วโมงต่อจนกว่าเลขสรุปจะพร้อม              <- UC-02 Exception Flow 2a
- FR-SBH-07 หากมีการกำหนดเวลาส่งของกองกิจและเกินกำหนดแล้ว ระบบต้องเสนอทางเลือกให้กรรมการไปที่ UC-11
  เพื่อขอผ่อนผันเวลาส่งช้า                                                <- UC-02 Exception Flow 4a

## Quality Requirements
- NFR-SEC-01 (อ้างอิง NFR ข้อ 21) ทุกการเข้าถึงฟีเจอร์ส่งข้อมูลชั่วโมง ต้องผ่านการยืนยันตัวตน (Login) ก่อน

## Acceptance Criteria
- [ ] AC-SBH-01 (FR-SBH-05)
      Given เลขสรุปโครงการพร้อมแล้ว และกรรมการตรวจสอบข้อมูลในไฟล์เรียบร้อย
      When  กรรมการกดยืนยันส่ง
      Then  ระบบสร้างไฟล์ Excel และส่งเข้าคิวของเจ้าหน้าที่กองกิจสำเร็จ
- [ ] AC-SBH-02 (FR-SBH-06)
      Given เลขสรุปโครงการยังไม่เสร็จ
      When  กรรมการเปิดหน้าส่งข้อมูลชั่วโมง หรือพยายามยืนยันส่ง
      Then  ระบบแสดงสถานะ "ขอเลขสรุปจากกองกิจ" และไม่อนุญาตให้ส่งข้อมูล
- [ ] AC-SBH-03 (FR-SBH-01)
      Given มีกิจกรรมที่ยังไม่จบและกิจกรรมที่จบแล้วปะปนกัน
      When  กรรมการพยายามเปิดหน้าส่งข้อมูลชั่วโมง
      Then  ระบบอนุญาตให้เปิดได้เฉพาะกิจกรรมที่มีสถานะ "จบแล้ว" เท่านั้น
- [ ] AC-SBH-04 (FR-SBH-02, FR-SBH-03)
      Given กรรมการเปิดหน้าส่งข้อมูลชั่วโมงของกิจกรรมที่จบแล้ว
      When  ระบบประมวลผลข้อมูล
      Then  ระบบดึงรายชื่อผู้เข้าร่วม/Staff และใช้ประเภทชั่วโมงที่กำหนดไว้ระดับกิจกรรม
            พร้อมสร้างไฟล์ Excel ตาม template ID/เวอร์ชันที่กำหนดใน config ของกองกิจให้ครบถ้วน
- [ ] AC-SBH-05 (FR-SBH-07)
      Given เกินกำหนดเวลาส่งข้อมูลชั่วโมงของกองกิจแล้ว
      When  กรรมการพยายามส่งข้อมูล
      Then  ระบบเสนอทางเลือกให้ไปที่ UC-11 เพื่อขอผ่อนผันเวลาส่งช้า
- [ ] AC-SBH-06 (NFR-SEC-01)
      Given ผู้ใช้ยังไม่ได้เข้าสู่ระบบ
      When  พยายามเข้าถึงฟีเจอร์ส่งข้อมูลชั่วโมง
      Then  ระบบปฏิเสธการเข้าถึงจนกว่าจะยืนยันตัวตนสำเร็จ

## Assumptions & Open Questions
- ASM-01 "เลขสรุปโครงการ" หมายถึงผลลัพธ์จาก UC-04 ที่ต้องเสร็จสมบูรณ์ก่อน จึงจะส่งข้อมูลชั่วโมงได้ (ตาม precondition)
- ASM-02 ข้อความในตาราง AC ต้นฉบับข้อแรกเขียนว่า "เมลสรุปโครงการฯ" ตีความว่าเป็น "เลขสรุปโครงการ"
  (คลาดเคลื่อนจาก OCR/พิมพ์ผิด) เนื่องจากตรงกับ Precondition และ Exception 2a
- ASM-03 โดยปกติการส่งข้อมูลชั่วโมงเป็นการส่งชั่วโมงย้อนหลังหลังกิจกรรมสิ้นสุด และไม่มีกำหนดส่งแบบคงที่
  จึงไม่ถือว่ามี deadline ปกติสำหรับฟีเจอร์นี้ เว้นแต่แต่ละกิจกรรมหรือกองกิจมีการกำหนดไว้ชัดเจน
- ASM-04 เทมเพลตไฟล์ Excel ของกองกิจจัดเก็บเป็น template ID/เวอร์ชันใน config ของระบบ
  และให้กองกิจอัปโหลด/จัดการผ่านหน้าแอดมิน ไม่ hardcode ไว้ในโค้ด
- ASM-05 ประเภทชั่วโมงถูกผูกไว้ระดับกิจกรรม (เลือกตอนสร้างโครงการใน UC-01) และไม่ใช่การกำหนดแยกตามรายบุคคล
- Q-01 Exception 2a ระบุว่าเป็น "จุด bottleneck ที่มีความเสี่ยงสูง" - ต้องการมาตรการเพิ่มเติม
  (เช่น แจ้งเตือนกองกิจให้ออกเลขเร็วขึ้น) นอกเหนือจากการบล็อกหน้าจอหรือไม่?
- Q-02 หากกรรมการตรวจสอบไฟล์ (ขั้นที่ 4) แล้วพบข้อมูลผิด (เช่น รายชื่อ/ประเภทชั่วโมงไม่ถูกต้อง)
  มีช่องทางแก้ไขก่อนส่งหรือไม่ หรือต้องย้อนกลับไปแก้จากต้นทาง (ระบบรายชื่อผู้เข้าร่วม/Staff)?
- Q-03 ขั้นที่ 5 ของ Main Flow ("ระบบส่ง/แสดงเอกสารของเจ้าหน้าที่กองกิจ") หมายถึงส่งเข้าคิว UC-07 ทันที
  หลังกรรมการยืนยัน หรือมีขั้นตอนยืนยันเพิ่มเติมอีกขั้นหนึ่งหรือไม่?
