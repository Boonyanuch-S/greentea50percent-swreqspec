# Feature: คิวเอกสารที่รอดำเนินการ พร้อมแจ้งเตือน (Pending Document Queue & Notification)
Spec ID: SPEC-DOC-007 | Source: US-07 | Use case: UC-07
Owner: ทีม A | Status: Draft v1 | Updated: 2569-09-09

## Goal
เจ้าหน้าที่สำนักงานคณะเห็นเอกสารโครงการที่สโมสรส่งเข้ามาในรูปแบบคิว "รอตรวจสอบ"
เรียงตามวันที่ส่งก่อน-หลัง และได้รับแจ้งเตือนทันทีเมื่อมีเอกสารใหม่เข้าคิว
เพื่อไม่ให้พลาดเอกสารและไม่ต้องรอให้สโมสรมาติดตามเอง

## Scope
### In scope
- รับเอกสารโครงการที่สโมสรส่งเข้าระบบ และนำเข้าสู่คิว "รอตรวจสอบ" ของเจ้าหน้าที่คณะที่เกี่ยวข้อง
- เรียงลำดับลิสต์ "รอตรวจสอบ" ตามวันที่ส่งเอกสารก่อน-หลัง (FIFO)
- แจ้งเตือนเจ้าหน้าที่คณะทันทีเมื่อมีเอกสารใหม่เข้าคิว
### Out of scope
- การส่งเอกสารโครงการโดยสโมสร (UC-06) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)
- การตรวจสอบ / อนุมัติ / ตีกลับเอกสาร (UC-08)
- การมอบหมายผู้ตรวจสอบเฉพาะราย (UC-10)
- ยืนยันตัวตนเจ้าหน้าที่ (UC-13) - ถือว่าทำสำเร็จแล้วก่อนเข้าฟีเจอร์นี้ (precondition)

## Constraints
- CON-TECH-01 ใช้ฐานข้อมูล MySQL ตามมาตรฐานฝ่าย IT ของมหาวิทยาลัย
- IF-IDP-01 ต้องได้รับผลยืนยันตัวตนจากระบบยืนยันตัวตนก่อนเข้าถึงลิสต์เอกสารของคณะ
- IF-NOT-01 ส่งการแจ้งเตือนผ่านระบบแจ้งเตือน (in-app/LINE) แบบ asynchronous
  (การบันทึกเอกสารเข้าคิวต้องไม่รอผลการส่งแจ้งเตือน)
- DOM-AUDIT-01 บันทึก audit log ทุกครั้งที่เอกสารเข้าคิว และทุกครั้งที่เจ้าหน้าที่เปิดดูลิสต์
  เก็บไม่น้อยกว่า 1 ปี

## Requirements
- FR-DOC-01 ระบบต้องนำเอกสารโครงการที่สโมสรส่งเข้ามา เข้าสู่ลิสต์ "รอตรวจสอบ" ของเจ้าหน้าที่คณะที่เกี่ยวข้องทันที
                                                                        <- US-07 AC ขั้น When
- FR-DOC-02 ระบบต้องเรียงลำดับลิสต์ "รอตรวจสอบ" ตามวันที่-เวลาที่ส่งเอกสารจากเก่าไปใหม่ (FIFO)
                                                                        <- US-07 AC ขั้น Then (ส่วนที่ 2)
- FR-DOC-03 เมื่อเอกสารเข้าสู่คิวสำเร็จ ระบบต้องส่งคำขอแจ้งเตือนไปยังเจ้าหน้าที่คณะที่เกี่ยวข้องทันที
  โดยไม่บล็อกการบันทึกเอกสารเข้าคิว                                     <- US-07 AC ขั้น Then (ส่วนที่ 1)
- FR-DOC-04 หากส่งการแจ้งเตือนไม่สำเร็จ ระบบต้องยังคงบันทึกเอกสารในลิสต์ตามปกติ
  และนำการแจ้งเตือนเข้าคิวส่งซ้ำ                                        <- ASM-03 (ไม่มีใน AC ต้นทาง ยืมแนวทางจาก IF-NOT-01)
- FR-DOC-05 ระบบต้องจำกัดให้เจ้าหน้าที่เห็นเฉพาะเอกสารของคณะ/หน่วยงานตนเองเท่านั้น
                                                                        <- ASM-04 (ไม่มีใน AC ต้นทาง อนุมานจาก "เจ้าหน้าที่คณะ")

## Quality Requirements
- NFR-PERF-01 การโหลดลิสต์ "รอตรวจสอบ": เวลาตอบสนอง p95 <= 2 วินาที ที่เอกสารค้างอยู่ไม่เกิน 500 รายการ
- NFR-REL-01 การแจ้งเตือนที่ส่งไม่สำเร็จ ต้องถูกส่งซ้ำภายใน 5 นาที
- NFR-USE-01 เจ้าหน้าที่รับรู้เอกสารใหม่ภายใน 1 นาทีหลังสโมสรส่งเข้าระบบ (นับจากเวลาที่แจ้งเตือนแสดงผล)

## Acceptance Criteria
- [ ] AC-DOC-01 (FR-DOC-01, FR-DOC-02, FR-DOC-03)
      Given สโมสรส่งเอกสารโครงการเข้าระบบ
      When  เอกสารเข้าสู่คิวของเจ้าหน้าที่คณะ
      Then  ระบบแจ้งเตือนเจ้าหน้าที่ทันที และเอกสารแสดงในลิสต์ "รอตรวจสอบ" เรียงตามวันที่ส่งก่อน-หลัง
- [ ] AC-DOC-02 (FR-DOC-04, NFR-REL-01)
      Given ระบบแจ้งเตือนไม่ตอบสนองขณะมีเอกสารใหม่เข้าคิว
      When  เอกสารถูกบันทึกเข้าลิสต์
      Then  เอกสารยังคงแสดงในลิสต์ตามปกติ และมีรายการแจ้งเตือนอยู่ในคิวส่งซ้ำที่กำหนดส่งภายใน 5 นาที
- [ ] AC-DOC-03 (FR-DOC-05)
      Given เจ้าหน้าที่คณะ ก. เข้าสู่ระบบ
      When  เปิดลิสต์ "รอตรวจสอบ"
      Then  เห็นเฉพาะเอกสารของคณะ ก. เท่านั้น ไม่เห็นเอกสารของคณะอื่น
- [ ] AC-DOC-04 (NFR-PERF-01)
      Given ลิสต์มีเอกสารค้างอยู่ไม่เกิน 500 รายการ
      When  เจ้าหน้าที่เปิดลิสต์ "รอตรวจสอบ"
      Then  p95 ของเวลาตอบสนอง <= 2 วินาที
- [ ] AC-DOC-05 (DOM-AUDIT-01)
      Given มีเอกสารเข้าคิวหรือมีการเปิดดูลิสต์
      When  เหตุการณ์นั้นเสร็จสิ้น
      Then  มี audit log ที่ระบุผู้เข้าถึง/เหตุการณ์ เวลา และรหัสเอกสารหรือคณะที่เกี่ยวข้อง

## Assumptions & Open Questions
- ASM-01 "เอกสารใหม่" หมายถึงเอกสารที่มีสถานะ = ส่งแล้ว และยังไม่ถูกกดตรวจสอบโดยเจ้าหน้าที่คนใด
- ASM-02 การเรียงลำดับ FIFO ใช้เวลาที่ระบบบันทึกการส่งสำเร็จ (server timestamp) ไม่ใช่เวลาบนอุปกรณ์ผู้ใช้
- ASM-03 นโยบายส่งซ้ำเมื่อแจ้งเตือนล้มเหลว (FR-DOC-04) อนุมานจากรูปแบบ IF-NOT-01/NFR-REL-02 ของ SPEC-BKG-001 ยังไม่ยืนยันกับทีมผลิตภัณฑ์
- ASM-04 การกรองสิทธิ์ให้เห็นเฉพาะเอกสารของคณะตนเอง (FR-DOC-05) อนุมานจากคำว่า "เจ้าหน้าที่คณะ" ใน user story ยังไม่มี AC ต้นทางยืนยันตรง
- Q-01 หากเจ้าหน้าที่ในคณะมีหลายคน ต้องแจ้งเตือนทุกคน หรือเฉพาะคนที่ถูกมอบหมาย? -> ถามเจ้าหน้าที่สำนักงานคณะ
- Q-02 เอกสารที่มีเจ้าหน้าที่คนหนึ่งเปิดดู/กำลังตรวจสอบแล้ว ยังต้องแสดงในลิสต์ "รอตรวจสอบ" ต่อไปหรือไม่? -> เกี่ยวเนื่อง UC-08
- Q-03 ช่องทางแจ้งเตือน (in-app / SMS / LINE) คืออะไร? -> ยังไม่ระบุใน user story นี้
