# แผนทางเทคนิค: นำเข้าข้อมูลเดิม

Spec ID: SPEC-IMP-008 | อ้างอิง: `spec.md` Draft v2 | Use case: UC-08

## 1. สรุปแนวทาง

1. สร้างหน้าสำหรับผู้มีสิทธิ์เลือกฟังก์ชันนำเข้าข้อมูลเดิมและอัปโหลดไฟล์ Excel/CSV ตาม `FR-IMP-01`, `ASM-04`
2. ตรวจสอบชนิดไฟล์ โครงสร้าง และข้อมูลในไฟล์ก่อนนำเข้า พร้อมแสดงตัวอย่างให้ตรวจสอบตาม `FR-IMP-02`, `IF-FMT-01`, `AC-IMP-04`
3. ตรวจจับไฟล์เดิมและขอการยืนยันก่อนอัปโหลดซ้ำตาม `FR-IMP-01`, `ASM-03`, `AC-IMP-03`
4. แยกขั้นตอนตรวจสอบไฟล์ออกจากขั้นตอนยืนยันนำเข้า เพื่อไม่บันทึกข้อมูลก่อนผู้ใช้ยืนยันตาม `FR-IMP-03`, `AC-IMP-01`
5. เก็บไฟล์และข้อมูลการนำเข้าในระบบหลังบ้าน 3 ปี และเปิดให้ค้นหาข้อมูลกิจกรรมตาม `FR-IMP-03`, `FR-IMP-04`, `ASM-03`, `ASM-04`

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| ImportBatch | รหัสการนำเข้า, ผู้ดำเนินการ, สถานะการตรวจสอบ, สถานะการนำเข้า, เวลาสร้าง, เวลาหมดอายุไฟล์ | `FR-IMP-01`, `FR-IMP-02`, `FR-IMP-03`, `DOM-ATOMIC-01`, `ASM-03` |
| ImportedFile | รหัสไฟล์, รหัสการนำเข้า, ชื่อไฟล์, ชนิดไฟล์, ลายเซ็นไฟล์สำหรับตรวจไฟล์ซ้ำ, ตำแหน่งจัดเก็บ, วันหมดอายุ 3 ปี | `FR-IMP-01`, `FR-IMP-03`, `ASM-03`, `AC-IMP-03` |
| Activity | รหัสกิจกรรม, ชื่อโครงการ, ปีการศึกษา, ข้อมูลกิจกรรมตามคอลัมน์ที่ยืนยันแล้ว | `FR-IMP-03`, `FR-IMP-04`, `ASM-02`, `Q-02` |
| Applicant | รหัสผู้สมัคร, ข้อมูลผู้สมัครตามคอลัมน์ที่ยืนยันแล้ว, รหัสกิจกรรม | `FR-IMP-03`, `FR-IMP-04`, `Q-02` |
| ImportError | รหัสข้อผิดพลาด, รหัสการนำเข้า, เลขแถว, รายละเอียดข้อผิดพลาด | `FR-IMP-05`, `AC-IMP-02`, `Q-01`, `Q-02` |

รายละเอียดคอลัมน์และชนิดข้อมูลของ `Activity` กับ `Applicant` จะยังไม่กำหนดจนกว่าจะตอบ `Q-02` และจะไม่สร้างฟิลด์นอกประเภทกิจกรรม/รายชื่อผู้สมัครตาม Out of scope และ `Q-02`.

## 4. API / หน้าจอ

| รายการ | Input / Output หลัก | รองรับ |
|---|---|---|
| หน้าฟังก์ชันนำเข้าข้อมูลเดิม | Input: ไฟล์ Excel/CSV; Output: สถานะการรับไฟล์และรหัสการนำเข้า | `FR-IMP-01`, `AC-IMP-03`, `CON-NFR-21`, `ASM-04` |
| `POST /api/imports/validate` | Input: ไฟล์; Output: ผลตรวจโครงสร้าง ตัวอย่างข้อมูล และรายการข้อผิดพลาดตามเลขแถว | `FR-IMP-02`, `FR-IMP-05`, `AC-IMP-02`, `AC-IMP-04`, `IF-FMT-01` |
| `GET /api/imports/{import_id}/preview` | Input: รหัสการนำเข้า; Output: ตัวอย่างข้อมูลและสถานะพร้อมยืนยัน | `FR-IMP-02`, `AC-IMP-04` |
| หน้าต่างยืนยันอัปโหลดซ้ำ | Input: การยืนยันของผู้ใช้; Output: ดำเนินการอัปโหลดต่อหรือยกเลิก | `FR-IMP-01`, `ASM-03`, `AC-IMP-03` |
| `POST /api/imports/{import_id}/commit` | Input: รหัสการนำเข้าและการยืนยัน; Output: ผลบันทึกข้อมูลและสถานะสำเร็จ/ล้มเหลว | `FR-IMP-03`, `DOM-ATOMIC-01`, `AC-IMP-01`, `Q-01` |
| `GET /api/activities` | Input: เงื่อนไขค้นหาที่ระบบรองรับ; Output: รายการกิจกรรมและข้อมูลที่นำเข้า | `FR-IMP-04`, `AC-IMP-01`, `ASM-04` |
| `GET /api/imports/{import_id}/file` | Input: รหัสการนำเข้า; Output: ไฟล์ที่เก็บไว้สำหรับผู้มีสิทธิ์ก่อนครบ 3 ปี | `FR-IMP-03`, `ASM-03`, `ASM-04` |

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| `CON-NFR-21` | middleware ของหน้าจอและ API ทุก endpoint ของฟีเจอร์นำเข้า | ใช้แล้ว |
| `IF-FMT-01` | ตัวตรวจชนิดไฟล์ โครงสร้าง และข้อมูลก่อนสร้าง `ImportBatch` ใน `POST /api/imports/validate` | ใช้แล้วบางส่วน; รายละเอียดคอลัมน์/ประเภทข้อมูลรอ `Q-02` |
| `DOM-ATOMIC-01` | `POST /api/imports/{import_id}/commit` ใช้การบันทึกแบบเป็นหน่วยเดียวและไม่เผยแพร่ข้อมูลที่นำเข้าไม่สำเร็จ | ยังไม่ได้ใช้ครบ เพราะต้องรอคำตอบ `Q-01` ว่าจะใช้ all-or-nothing หรือ partial import |

## 7. ลำดับงาน

1. กำหนดสิทธิ์และ middleware สำหรับฟีเจอร์นำเข้าตาม `CON-NFR-21`, `NFR-SEC-01`, `ASM-04`, `AC-IMP-05`
2. ยืนยัน schema คอลัมน์และชนิดข้อมูลก่อนสร้างตัวตรวจสอบตาม `IF-FMT-01`, `Q-02`
3. สร้างโมเดล `ImportBatch`, `ImportedFile`, `Activity`, `Applicant` และ `ImportError` ตาม `FR-IMP-03`, `FR-IMP-04`, `ASM-02`, `ASM-03`
4. สร้างหน้ารับไฟล์และกลไกตรวจไฟล์ซ้ำตาม `FR-IMP-01`, `ASM-03`, `AC-IMP-03`
5. สร้าง validation และ preview พร้อมเลขแถวผิดพลาดตาม `FR-IMP-02`, `FR-IMP-05`, `AC-IMP-02`, `AC-IMP-04`
6. ตัดสินใจและสร้างกระบวนการบันทึกแบบ atomic หรือ partial ตามคำตอบ `Q-01` และ `DOM-ATOMIC-01`
7. สร้าง endpoint ยืนยันนำเข้า การเก็บไฟล์ 3 ปี และการค้นหาข้อมูลตาม `FR-IMP-03`, `FR-IMP-04`, `ASM-03`, `AC-IMP-01`
8. รันทดสอบตาม `AC-IMP-01` ถึง `AC-IMP-05` และตรวจสิทธิ์ตาม `CON-NFR-21`, `ASM-04`

## 8. สิ่งที่ยังไม่ทำ

- `Q-01` พฤติกรรมที่แน่นอนของการไม่ import ข้อมูลบางส่วน: จะปฏิเสธทั้งไฟล์ (all-or-nothing) หรือ import เฉพาะแถวที่ถูกต้องแล้วรายงานแถวที่ผิด — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-02` โครงสร้างไฟล์ที่รองรับ ได้แก่ คอลัมน์ที่จำเป็นและประเภทข้อมูลแต่ละคอลัมน์ — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- `Q-04` ขนาดไฟล์สูงสุดและจำนวนแถวสูงสุดต่อการนำเข้าหนึ่งครั้ง — ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ

### ข้อจำกัดที่ยังไม่ตัดสินใจแทนทีม

- ยังไม่กำหนดวิธีจัดการเชิงระบบเมื่อชื่อโครงการซ้ำภายในปีการศึกษาเดียวกัน เพราะ `ASM-02` ระบุเงื่อนไขความไม่ซ้ำ แต่ไม่ได้ระบุข้อความแจ้งเตือนหรือจังหวะที่ต้องปฏิเสธการนำเข้า — ส่วนที่เกี่ยวข้องจะยังไม่สร้างเกินกว่าการตรวจเงื่อนไขตาม `ASM-02`
- ยังไม่กำหนดวิธีค้นหาและฟิลด์ที่ต้องแสดง เพราะ `FR-IMP-04` ระบุเพียงว่าสืบค้นได้ — ส่วนที่เกี่ยวข้องจะยังไม่สร้างเกินกว่าจุดเชื่อมต่อการค้นหาตาม `FR-IMP-04`
